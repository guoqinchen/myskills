# Find Unknowns

**地图**（你告诉 AI 的）≠ **地形**（实际约束）→ **未知**就是差距。

发现未知越早，代价越低。

## TL;DR

- **核心流程**：挖假设 → 扫盲区 → 展方案 → 做原型 → 追问 → 引用 → 计划 → 记偏差 → 打包 → 测验
- **3 个阶段检查点**（原 5 个）：**探索** → **决策** → **验证**
- **新增「挖假设」**：前置挖掘用户话术中的隐式假设
- **自适应追问**：先问关键的 1-2 个，根据回答动态深入
- **AI 主动引用**：AI 先搜索代码库，不等用户手动提供

## 阶段检查点

| 阶段 | 步骤 | 检查点 |
|---|---|---|
| 🟡 **探索** | 挖假设 → 扫盲区 → 展方案 → 做原型 | 方向已明确，所有隐藏假设已暴露 |
| 🔵 **决策** | 追问 → 引用 → 计划 | 关键决策已澄清，计划已确认 |
| 🟢 **验证** | 记偏差 → 打包 → 测验 | 测验通过，偏差已记录 |

**快速通道**（简单任务或有经验者）：挖假设 → 追问 → 记偏差

---

## 显性检查点标记

🔴 **CHECKPOINT 1** — 挖假设完成后：用户确认所有假设无误  
🔴 **CHECKPOINT 2** — 探索阶段完成后：用户确认方向无遗漏  
🔴 **CHECKPOINT 3** — 决策阶段完成后：用户确认关键决策  
🛑 **STOP** — 测验未通过：必须讲清楚所有答错部分才能继续合并

## Steps

### 0. 挖假设（前置·必做）

在任何需求描述后立即执行。**不要跳过**。

从用户话术中提取 3-5 个隐式假设，逐一追问。

**格式**：`[领域] 你说「X」→ 隐含假设「Y」→ 真的是 Y 吗？A/B/C?`

**示例**：

| 用户说 | 隐含假设 | 追问 |
|---|---|---|
| 「做一个**患者**管理系统」 | 患者=住院患者 | 「患者是住院患者、门诊患者、还是两者都有？」 |
| 「用户注册后**自动登录**」 | 用户=注册用户 | 「这里的用户是注册用户还是匿名访客？未登录能做什么？」 |
| 「**实时**同步数据」 | 实时=秒级延迟 | 「你说的实时指秒级、毫秒级、还是最终一致？」 |
| 「要保证**数据安全**」 | 安全=数据库加密 | 「你关心的是传输加密、存储加密、访问控制、还是审计日志？」 |
| 「用**微服务**架构」 | 微服务=必然更好 | 「微服务对你场景的具体好处是？你考虑过单体+模块化拆分吗？」 |

**完成标志**：用户确认所有假设无误，或修正了错误假设。

---

### 1. 扫盲区

| 触发条件 | 操作规范 | 完成标志 |
|---|---|---|
| 用户说「没做过」「不懂某领域」「不知道从哪入手」 | 概念卡片 3-5 个，每个后跟「你知道这个吗？」 | 用户确认盲区无遗漏 |

**卡片格式**：`**[概念名]** — 定义 + 3 关键点`

> **[REST API]** — 基于 HTTP 的资源导向接口规范。关键点：资源导向、无状态、统一接口。你知道这个吗？
>
> **[消息队列]** — 异步解耦的消息传递中间件。关键点：削峰填谷、生产者/消费者、持久化。你知道这个吗？

---

### 2. 展方案

| 触发条件 | 操作规范 | 完成标志 |
|---|---|---|
| 原因不确定、路径不唯一、需要选型 | 3-4 方案表格对比，含成本和推荐场景 | 用户表达方向偏好 |

**对比维度**：方案 | 场景 | 优势 | 劣势 | 难度 | 成本

---

### 3. 做原型

| 触发条件 | 操作规范 | 完成标志 |
|---|---|---|
| 用户说「不确定想要什么」「看看效果」 | 代码片段 ≤50 行 / 数据示例 / 流程图，标注关键差异点 | 用户确认方向或指出修改点 |

---

### 4. 追问（自适应深度）

| 触发条件 | 操作规范 | 完成标志 |
|---|---|---|
| 架构模糊、需求不完整 | **分层追问**：先 1-2 个关键问题 → 看回答决定下一层。每题提供 2-3 选项 | 所有架构级决策已澄清 |

**追问优先级（按领域裁剪）**：

| 领域 | 第一层（必问） | 第二层（按需） |
|---|---|---|
| 通用 | 数据模型 / 接口约定 | 交互流程 / 技术栈 |
| **数据建模** | 实体定义 / 关系类型 / 约束 | 粒度 / 历史 / 审计 |
| Web 开发 | 用户角色 / 认证方式 | 部署环境 / 扩展性 |
| AI/ML | 数据来源 / 评估标准 | 模型选择 / 部署方式 |

**反直觉追问**：对用户最自信的点提问。
> 「你说「这个很明确」——有没有可能在某些场景下不成立？比如数据量到 100 万行时？」

---

### 5. 引用（AI 主动）

| 触发条件 | 操作规范 | 完成标志 |
|---|---|---|
| 上下文缺失、描述不清 | **AI 先主动搜索**：目录 / README / schema 定义 / 相邻模块代码 → 无结果再要求用户提供 | 获得足够参考物 |

**搜索优先级**：README / 配置文件 → 数据库 schema → 接口文档 → 相邻代码风格

---

### 6. 计划

| 触发条件 | 操作规范 | 完成标志 |
|---|---|---|
| 多组件变更 | 阶段 / 任务 / 时间 / 依赖 / ⚠️风险。关键决策前置 | 用户确认关键决策 |

---

### 7. 记偏差

| 触发条件 | 操作规范 | 完成标志 |
|---|---|---|
| 执行中浮现 edge case 或需求变更 | 写入 `implementation-notes.md`，格式见下 | 每个偏差记录并附取舍理由 |

**格式**：`[时间戳] 问题 → 决策方案 → 取舍理由 → 验证点`

---

### 8. 打包

| 触发条件 | 操作规范 | 完成标志 |
|---|---|---|
| 需团队审查 | `design-doc-{日期}.md`：背景 / 方案对比 / 最终方案 / 关键决策 / 风险 / 计划 | 审查者可独立理解每个决策 |

---

### 9. 测验

| 触发条件 | 操作规范 | 完成标志 |
|---|---|---|
| 用户要合并 / 确认 | 3-5 题覆盖核心变更点；**快速模式 1-2 题** | 全部答对 |

---

## Roadmap

| 场景 | 步骤组合 | 时长 |
|---|---|---|
| 简单任务 | 挖假设 → 追问 → 记偏差 | 短 |
| ★ **数据建模** | 挖假设 → 追问 → 做原型 → 引用 → 记偏差 → 测验 | 中 |
| 复杂功能 | 做原型 → 追问 → 引用 → 计划 → 记偏差 → 打包 → 测验 | 长 |
| 陌生领域 | 挖假设 → 扫盲区 → 做原型 → 记偏差 → 测验 | 中 |
| 协作 / 评审 | 引用 → 计划 → 记偏差 → 打包 → 测验 | 长 |
| 故障诊断 | 挖假设 → 展方案 → 追问 → 记偏差 | 短 |

## 失败模式与 Fallback

| 触发条件 | 一线修复 | 兜底 |
|---|---|---|
| 用户拒绝回答 | 换种表述，用具体例子 | 标记「待确认」，基于合理假设继续 |
| 无法提供引用材料 | AI 主动搜索代码库 | 用标准最佳实践 + 标注假设 |
| 对方案都不满意 | 追问具体不喜欢的点 | 暂停，需更多信息 |
| 跳过步骤 | 给「最小信息」选项；**简单任务允许跳过测验以外的步骤** | 复杂变更必检 |
| 发现新未知 | 暂停，回到挖假设或扫盲区 | 标记偏差并记录 |
| 反馈与先前矛盾 | 指出矛盾，请求澄清 | 以最新反馈为准，记录原因 |
| 用户说「按你的方案」 | 追问「你理解这方案意味着什么？」 | 要求用户用自己的话重述 |

## 反例与黑名单

| # | 反模式 | 原因 |
|---|---|---|
| 1 | 跳过追问直接输出方案 | 错误假设比无方案更糟 |
| 2 | 用户说「不知道」时直接给答案 | 用户需要理解而非结果 |
| 3 | 只给一个方案不展示取舍 | 用户看不到全貌 |
| 4 | 一次性抛出所有追问 | 用户信息过载，无法有效回答 |
| 5 | 不记录偏差 | 隐性假设积累无法追溯 |
| 6 | 测验放水 | 合并未经理解的变更风险极高 |
| 7 | 不验证用户理解核心概念 | 用户可能点头但实际不明白 |
| 8 | 忽略用户已有知识 | 先挖假设再扫盲，避免浪费时间 |
