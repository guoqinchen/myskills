# 执行安全：审计、防线、清单、确认（execution-safety）

本 reference 覆盖执行阶段的安全保障机制，收口于 Step 2（规划门禁）、Step 3（执行）。
引用以下机制（顺序对应执行流程）：

---

> **可视化闸门标记（跨 reference 通用）**：`🔴 CHECKPOINT` ＝ 到此必须停下等用户确认，未确认不得继续；`🛑 STOP` ＝ 立即中止且不得自行恢复（安全 / 越权 / 不可逆场景）。与进度标记 `[检查点]` / `[PLAN-UPDATE]`（批处理推进用，**无需**用户确认）语义不同，禁混用。

## 规划门禁（PLAN-GATE，Step 2 启用）

🔴 CHECKPOINT 复杂 / 大项目档在进入修改阶段前必须通过，按三池结构逐项打勾。轻量档免本门禁、常规档免三池（均见 `routing.md`「档位 → 最小执行集」）；虽通过但触发异常 → 强制中止。

**plan 落点（L1）**：三池结论写入 `Plan/N. 中文名_plan.md`，须含独立 `## 状态` 节（`规划中`/`进行中`/`已完成`/`已中止`）与 `## 不卡死计数` 节；核心目录改动前 `plan_guard` 只认该形态，缺则被拦。

### A 池：无条件核心项（10 项，逐项打勾）

```
☐ A1. 需求→步骤映射完整：每条用户需求/约束都有对应步骤，无遗漏需求
☐ A2. 步骤含出口校验：每步有可判定的完成标准（不写"然后检查"式空话）
☐ A3. 涉及数据 / 外部依赖已标注：表结构、接口、三方库、配置项显式列出
☐ A4. 风险点已识别并写缓解：每风险有对应缓解或回退动作
☐ A5. 验证方式已定义：每步写明证据类型（命令+输出/测试报告/截图/API响应）
☐ A6. 回滚 / 恢复机制已定义：可逆操作标注 .bak/事务回滚点，不可逆操作标注用户确认闸门
☐ A7. 批量范围已确认：文件数 / 记录数 / 受影响 API 数明确
☐ A8. 安全触发面已评估：外部输入/权限/数据库/文件上传/API/后台操作逐项过
☐ A9. 用户定制 / 人工干预文件已遍历：不遗漏手工改动，避免覆盖
☐ A10. 中断点与恢复路径已标注：plan 内写明失败后回退到哪一步
```

☐ B2. 涉新依赖 → 许可证兼容 + 已知漏洞已排查（引前审查门禁）
☐ B3. 涉并发 / 幂等 → 竞态、重复提交、分布式锁已考虑
☐ B4. 涉性能敏感路径 → 已标注需基准对比，禁止无基线声称"提升"
☐ B5. 涉外部系统 / 接口 → 影响已评估，调用方兼容性已确认
☐ B6. 涉测试 → 测试集已选定或确认无需新测试
☐ B7. 涉批处理 → 试点 + 备份 + 分批策略已就绪
☐ B8. 涉不可逆操作 → 用户确认闸门已标注（删/重命名/DDL 不单凭图谱）
☐ B9. 涉多文件 → 依赖影响面已查（P1 图谱闭包 + grep 复核）
☐ B10. 涉命令行 / 脚本 → 参数完整无硬编码路径
☐ B11. 涉外部输入 / 接口输出 / 外部依赖 → 边界已声明：输入（类型 / 空值 / 超长）+ 输出（值域 / 错误码）+ 异常路径（依赖不可用 / 超时 / 并发）；保护型守卫 / 锁类约束须声明适用边界 + 豁免边界〔纯内部同构改动 N/A〕
☐ B12. 方案需回读 → 已回读确认格式无乱码/截断

### C 池：规模触发项（规模超阈值才启用）

```
☐ C1. 修改文件 ≥ 5 或修改点 ≥ 10 → 每 5 文件落一次 CHECKPOINT（进度 + 已验证证据）
☐ C2. 任务超长 / 跨 Wave → 拆子任务链式执行，每 Wave 完成落 handoff 检查点
```

### 规划自审（PLAN-GATE 通过后、进入 Step 3 前执行）

1. **占位符扫描**：方案中不得残留 `TODO`、`待补充`、`...`、`{未定义}` 等占位符，全部替换为实值或显式标注"待用户提供"
2. **类型 / 签名一致性**：方案涉及的函数签名、表字段、接口参数、配置键名与实际代码一致，禁止凭空臆造
3. **需求→步骤映射**：反向核对——每个步骤都对应至少一条需求；无需求的步骤标注"防御性/重构性"，说明必要性
4. **引用点实码 trace**：方案中引用的每个函数/变量/配置点，必须用实码 grep 确认存在且签名一致，禁止凭记忆或猜测引用；引用点 trace 结果写入 plan 对应步骤，作为写码前确认的输入

### 方案成形自检（复杂档 / 大项目档方案成型前逐项过，任一未过不得进 Step 3）

**一、方案五段（缺段即该档未执行）**：① **输入 / 输出 / 约束**——输入域（类型 · 空值 · 超长）、输出契约（值域 · 错误码）、硬约束清单；② **方案与取舍**——≥2 条候选 + 各自 trade-off + 反选理由 + 撤销条件；③ **边界与失败模式**——失败模式清单（每条定处置档位，见下）+ 二阶效应；④ **权衡结论**——冲突关切点的取舍结论 + 该取舍的代价；⑤ **产出与局限**——可独立验收的交付物 + 未覆盖 / 未验证清单。

**二、六类必过动作（逐条自检）**：1 多路径与取舍已考虑（≥2 候选 + trade-off）；2 目标 / 约束 / 成功判据 / 潜在歧义已识别；3 边界、失败模式与二阶效应已浮出；4 产出结构按可读性与可操作性组织；5 对局限诚实、结论可行动（禁「应该 / 差不多」式断言）；6 领域既有事实已回源核实，且**每步结论锚定到具体前序输出**（命令或文件 + 关键片段），禁以「我记得 / 应该是 / 前面说过」承接。

**三、失败模式处置分档**（触发：新增校验 / 清洗 / 校验后写入 / 批量处理 / 外部依赖调用；须穷举维度：空值 / 非法值 / 超长 / 超时 / 依赖不可用 / 并发冲突 / 重放 / 部分成功）：每条须定档之一——**拒绝**（阻断 + 错误码）｜**放行 + 标记**（标记须可被下游消费）｜**汇总上报**（须指定报告通道）。禁止：整批因单条失败而静默中止；全部降级为警告而无「拒绝」档；分档未指定产出通道。**验收**：E2E 须同时覆盖「拒绝」与「放行 + 标记」两态（只验单档 = 未覆盖）。

**四、三清单**：

- **二阶效应**（触发：新增 / 删除机制、改缓存策略或 TTL、改并发或事务边界、改共享配置、改跨端同步）：每条给「触发链 A⇒B⇒C」+ 观察指标 + 兜底；**枚举后判定无二阶效应时须显式声明「无二阶效应」**（禁静默）。边界：一阶直接依赖走依赖影响面门禁，兄弟调用点走覆盖完整性枚举。
- **歧义清单**（触发：口径不明 / 边界模糊 / 多解，含用户未察觉的隐含分歧）：每条定「澄清」（走澄清策略分级）或「声明假定」（假定值 + 证伪条件 + 触发复盘的时机）；禁默默挑一种解释实现，禁留到验收阶段才暴露。
- **未知清单**（触发：进入新任务 / 切换方案 / 关键决策前）：列出「做出下一步决策还缺什么信息」，每项指向具体对象（某文件 / 配置 / 运行时行为 / 调用方）+ 闭合方式（命令或读取动作）+ 闭合结果；未闭合项显式标注并说明对决策的影响，禁以假定冒充已闭合。

**五、判据间冲突裁决次序（前者压后者）**：安全 · 不可逆 ＞ 证据门槛（未见失败不修改）＞ 范围纪律（顺手修 = 越界）＞ 止损（触下限即停）＞ 原样验收（探针删后重跑）＞ 可读合并（原始计数 / 完整状态）。本序只裁**判据间**冲突，不越过铁律、门禁与用户明示要求。

## 写码前实码确认

修改或生成代码前，必须完成：

1. **读文件**：`read_file` 目标文件，确认上下文、编码、插入位置
2. **搜索关联**：`search_content` 在项目中搜关键函数名/类名/表名，确认无遗漏引用
3. **冲突检查**：确认当前文件无正在进行中的未合并变更

三项均完成后才允许进入修改操作。跳过任一项 → 退回 Step 2。

**外部检索六律（L1，写码前实码确认的域外形态）**：

1. **未识别实体先查证**：名称·版本·接口·报错串（含短名缩写）先查证再作答，禁凭部分识别推定。
2. **用户给出的 URL 与提示暗示存在的资源，须实抓/实读**核实后再依赖。
3. **查询词简短、先宽后窄**：禁重复近似查询。
4. **检索量随复杂度缩放**：单事实 1 次 / 中等 3-5 / 深查 5-10；超预算改形态（分批·子代理）并披露。
5. **权威来源对照须申报（L1）**：官方文档/规范与本技能假设或既有实现冲突时须**显式申报**，**无冲突亦须报**——"未见冲突"是结论而非默认；采信分级——一般采信，SEO 与无共识领域存疑并标注。
6. **反确认偏误**：结论存在 ≥2 种候选解释/方案时，检索须同时覆盖**排除备选**的方向（只找支持当前偏好的证据＝确认偏误）；「请求/现象里最具体的细节」通常正是要核的点，禁当旁注跳过。

**外部事实回源（L1，检索六律的域外形态）**：

- 判据＝「记住 ≠ 测试」（记住的是当时的答案，不等于现在仍成立）——凡绑定世界当前状态的事实（版本·依赖行为·接口契约·兼容矩阵·法规·价格）下结论前须先用工具验证；不认识的专有名词（库·产品·服务·报错码）默认先查；流畅而过时的自信答案比"不认识"更糟。
- 排名/对比中不认识的实体逐个单查，禁"抽查一个后外推其余"。
- 链接/标识符只能取自本会话已出现过的工具结果或用户输入，禁凭记忆构造 URL/ID（含"看似合理"的路径）。
- 采纳的主张须带证据（命令输出 / 文件行号 / 官方文档）或显式标为推断，禁把推断写成事实。

### 诊断先行（写操作前强制输出一行）

三项完成后、动手前必须输出一行诊断，把行动与证据绑定，防止"分析正确但不行动"：

```
[诊断] 问题是___；证据___；已查errors:命中N条；规模:Plan/N|TrivialFix
```

- **证据须标来源**：错误原文 / 源码上下文 / 复现实验 / 官方文档 / 历史先例；未验证的归因不是诊断。
- **下一步必须落到诊断指向的位置**：诊断指向某文件 / 函数 / 配置 / 数据流时，下一步即处理该处；不处理须写明理由。
- **隐含假设**：本次判断依赖但尚未验证的前提，有则逐条列出（无则省略），供用户一眼否决。
- 只允许"事实 + 来源 + 下一个动作"三要素，禁写成方案书。
- 读操作不限（只读检索 / 查询无需输出）。
- **无机械兜底**：`[诊断]` 由 Agent 自证（SELF-AUDIT 流程完成度表 Step1 行核对，Trivial Fix 同口径）。

## 审计修复分离

适用于代码审查、Bug 诊断、重构建议等场景：

- **审计阶段**：只读操作，收集证据（问题清单、堆栈、日志、复现步骤），禁止修改任何文件
- **修复阶段**：审计阶段结束后，输出结构化诊断结论，经确认后才进入修改。**「确认」只指两种情况**：用户本轮只要求审查 / 诊断 / 评估（交付物＝结论），或修复方案涉破坏性 · 安全 · 不可逆动作。用户已明确要求"审查并修复"时**不止步**——按结论直接修复，并在交付中并列「审计证据 + 修复证据」两段

两阶段不可交叉。审计未完成前改代码 → 视为未完成审计，退回重做。

审计输出格式（修复阶段的前置输入）：

```
## 审计结论
- 问题定位: {文件:行号}
- 根因分类: {框架行为/配置/缓存/竞态/逻辑错误/...}
- 影响范围: {受影响模块/功能}
- 修复方向: {最小改动方案}
- 验证方式: {如何确认修复有效}
```

### 阶段3出口 GATE-CHECK（阶段3→4 出口核验，禁仅写"通过"）

`[门禁核查] 证据清单:` ≥1 条/改动文件（GATE-CHECK 下限），每条附工具原始输出（curl/assert/php -l/read_file/DOM 断言）。清单空 → 禁入阶段4。

## 失败计数与升级

> 本节点是失败次数与升级动作的**唯一定义源**；其它 reference 提及失败次数一律引用本节点，不另立阈值。

### 一、计数口径（先判"算不算一次失败"）

- **一次失败** = 同一子目标的一次实际方案未达**动手前已定义的验收**；计数单位是**子目标**，不是命令（同一子目标内的多条命令合计为一次尝试）。
- **不计数**：命令退出码红绿本身 / 预期复现（复现失败即成功）/ 搜索无匹配 / 仍在运行的任务 / 读文件失败。
- 有新证据的探索不强行掉头；同一假设重复且无新信息 → 必须换**本质不同**的实验。
- 数字口径：**已确认失败 n 次 → Lx**（0–1 次 L0 / 2 次 L1 / 3 次 L2 / 4 次 L3 / 5 次+ L4）；正在做第 3 次尝试 ≠ 已失败 3 次，历史计数未知时写"计数未知"，不编数字。
- 计数写入 `_plan.md`「不卡死计数」节（跨会话不重置）；无 `_plan.md` 时记入对话流并在交接中延续。

### 二、分级升级表

| 已确认失败 | 等级 | 强制动作 |
| ---------- | ---- | -------------------------------------------------------------------------------------------------------------- |
| 0–1 次 | L0 | 继续当前方法，补足证据 |
| 2 次 | L1 | 换一条**本质不同**的方案（换参数 / 换函数名不算换方案） |
| 3 次 | L2 | 搜索（报错原文 / 官方文档 / 多角度关键词）+ 读失败位置原始上下文 + 列出 3 条假设 |
| 4 次 | L3 | 完成 7 项检查清单（见下），逐项给证据；不可用项写明替代路径，不伪造打勾 |
| 5 次+ | L4 | 极限穷尽（当前方法全部变体 + 换工具 / 技术栈 / 抽象层）；仍不成立 → 进 `delivery-assurance.md`「穷尽后的结构化失败报告」 |

L3 的 7 项清单：① 逐字读完失败信号 ② 工具搜索过核心问题 ③ 读过失败位置原始上下文 ④ 所有假设工具确认 ⑤ 试过相反假设 ⑥ 最小范围复现 ⑦ 换过工具 / 方法 / 角度 / 技术栈。

### 三、失败模式三分类（决定"换不换方法"）

| 模式 | 检测信号 | 动作 |
| -------- | ---------------- | ------------------------------------------------------ |
| 原地打转 | 同一错误重复出现 | **禁止重试同一方法**；列 3 条本质不同的策略再动手 |
| 在收敛 | 每次错误不同 | 保持方向并增加结构：每个新错误告诉你什么 |
| 振荡 | 部分重复部分新 | 检查是否在两方案间来回；选定**错误最新**的方向提交 |

### 四、换方法链（失败模式 → 本技能落点）

| 失败模式 | 换方法落点 |
| -------------------------------------- | --------------------------------------------------- |
| 方向存疑（需求 / 方案本身可能不对） | `spec-driven-development` + `architecture-decision` |
| 未验证归因、凭记忆下结论 | 先 `search_content` 搜报错原文，再决定是否问用户 |
| 症状修补、反复打补丁 | `root-cause-debugging`（追溯上游成因） |
| 只顾一个点、质量分布错 | `code-review` + `refactoring` |
| 性能无基线、凭感觉 | `performance-benchmark` |
| 被动等待、等指示 | 本文件「写码前实码确认」+ `task-decomposition-and-execution.md` |

### 五、达上限后的交付

`_plan.md`「不卡死计数」达上限 → 暂停该方向，列 2–3 条替代方案（不同策略，非参数微调）：

1. 说明各方案的成本、风险与验证方式
2. 标注**推荐项**与**已验证 / 未验证**状态
3. 仅当推荐项**已验证**（有实测证据）才允许「超时无回复按推荐项推进」；推荐项未验证则交用户决断，禁自动推进带病方案
4. 无回复按 `delivery-assurance.md`「确认超时默认规则」处理

### 六、失败签名口径（计次前先判"算不算同签名"）

**失败签名**＝失败信号的**稳定特征**（报错类型 + 关键标识串 / 失败断言名），**不含**时间戳、行号、临时路径、随机后缀等易变量。同签名重复＝无新信息，计入「不卡死计数」；换签名＝有新信息＝不计次。"正在做第 N 次尝试"不等于失败 N 次；读文件成功、预期复现、搜索无匹配、仍在运行的任务均不机械计次。

### 七、失败计数事件判据（防"刷失败次数"与"误判卡死"）

| 事件 | 处理 |
| --- | --- |
| 同一失败被日志/总结重复展示 | 同一事件，**不重复计次** |
| 测试刻意复现旧缺陷而失败 | **复现证据**，不算一次修复失败 |
| `grep` 无匹配 / 退出码非零但未达该实验的约定验收 | **信息**，按该实验的约定验收判定，不按退出码自动算失败 |
| 读文件·打印状态成功但原问题仍在 | **不归零**、不宣布突破 |
| hook 回显 / 状态文件 / 工具观察（含计数与错误提示） | **待核对参考**：须先核对任务身份与验收口径再决定是否并入计数；hook 只提供观察值，不判定失败、突破或完成 |
| 有进程/任务句柄正在运行 | 观察**同一句柄**；一次观察超时**不是终止证据**，禁盲目重启或杀掉 |
| 缺少权限/凭据/外部服务不可用 | 保留事实，完成可做部分后**精确交接**；禁以无限重试制造勤奋 |
| 目标验收真实通过 | 该子目标完成；核对其余子目标仍未通过者，禁以单点成功宣布整体完成 |

### 八、归因先行（换路/绕行前的硬门，L1）

遇非预期响应或失败（报错·异常返回·断言失败·结果不符预期），**换路/绕行/改变方案前须先归因**——给出原因判定（原因假设 + 验证方式，或已确认的证据）并写明「原路为何不通（已确认原因）」；未归因不得换路。禁以"换个方法再试"充当失败处理（＝随机游走）；绕行（workaround）须显式标注并记入技术债（收尾「待办」）。

**工具类失败特则（归因先行的工具侧）**：编辑/命令失败后，先三查再动作——① 工具语义（写入原子性/回滚行为，实测）② 实际生效范围（查磁盘/状态实况，禁假设）③ 最小重放；三查结果并入归因说明。
**工具冒烟**：首次使用某工具/接口（或对其行为不确定）时，先发最小泛调用验证行为与返回形态，再发正式调用；冒烟结果并入下一步理由。
**采集命令设计**：组合命令兼顾三性——容错（缺项不掩主结果）、限幅（head/tail 防爆量）、防噪（排除无关）；一条命令多目标时每段职责可数。

### 九、换框三轴（"列 2-3 选项"的生成器）

1. **换视角**：用户视角（从期望行为倒推）/ 攻击者视角（怎么让这段崩）/ 新手视角（忘掉已知，像初次读）。
2. **换抽象层**：上移（调用方期望什么，问题可能在调用侧）/ 下移（底层实际在做什么，读源码不读文档）/ 平移（有无完全不同的库/工具/入口可绕过）。
3. **换约束**：不能改这个文件怎么办 / 只有 5 行预算怎么办 / 需求本身是否合理 / 上一个能工作的状态是什么，从那里重出发。
4. **反转（最激进，前三层都走过或同签名已重复时用）**：如果这个报错其实是 feature，什么场景下当前行为是对的 / 如果问题不在代码而在环境·数据·配置 / **重审已排除项**——把 plan/交接里的「已排除」清单拉出来逐条重验。

**选项合格判据**：① 三轴中至少两轴各出 ≥1 项（第 4 条反转层按需取用）；② 各项互不相同——换参数、换函数名、换同族 API **不算**换方案；③ 每项标推荐项 + 已验证/未验证；④ 禁止以"再试一次/再调一次"充当新选项。

**禁止行为**：同参数微调绕过计数器；换一句等价表述重试同一思路；把"再提交一次命令"当"换了方案"。

## 解题方法论（按任务类型选打法，单源）

> 任务类型决定**主打法**；连续失败时**换打法不换目标**。换法前先过三问：① 当前打法的核心步骤走完了吗（没走完＝加压力不换法）② 失败是打法不对还是执行不到位（执行不到位＝不换法）③ 新打法能解决当前失败模式吗（不能＝别换）。

| 任务类型 | 主打法 | 硬要求（缺项即该打法未执行） |
| --- | --- | --- |
| 修 Bug / 排障 | **RCA 根因分析 + 蓝军自攻击** | ① 5-Why 追到根因并**验证根因假设**（"改完不报了"不等于根因）；② 方案落地前先当自己的蓝军攻一遍：最可能在哪失败、哪个边界会打脸、**用户真实目标是否被偷换** |
| 线上应急止血（紧迫故障） | **先止血后根因** | ① 止血动作取最小回滚/关开关/回退包（按不可逆纪律留回滚点＋确认）；② **止血≠修复**——须留「根因票据」（另立 plan 追根因，禁以止血完成关闭任务）；③ 证据＝止血前后同指标对比 |
| 新增功能 / 改实现方式 | **五步工作法（严格按序）：质疑需求 → 删除 → 简化 → 加速 → 自动化** | ① 先问"这一步真的需要吗、能不能不做"；② **没删掉 ≥10% 的步骤说明删得不够**；③ 禁从第 3/5 步起手（最常见错误＝直接优化一个本不该存在的东西） |
| 调研 / 信息不足 | **搜索先于判断** | 报错原文·官方文档·源码先查；禁凭记忆/摘要下结论（基于实码铁律） |
| 性能优化 | **基准对比** | 改前有基准（耗时/行数），改后有对比；禁无基线声称"提升" |
| 架构 / 技术选型 | **从用户结果倒推 + 候选 ≥2** | 先写"用户看到的最终效果"；候选≥2 + 反选论证 |
| **连续失败 / 思维固化（同签名≥2）** | **changed_action 硬门** | 下一轮动手前须先在 plan「不卡死计数」表写明四格：`上轮错误假设` / `新证据` / `下一步为什么本质不同` / `用什么验证`。**未写明 ⇒ 禁止继续原路径**（换参数、换函数名、换同族 API 都不算本质不同） |
| 审计／审查（只发现不改码） | **只读取证打法** | ① 审计期 **0 改码**：全量只读→汇总清单→用户确认后另立修复 plan；② 发现落 `_audit_logic_<主题>.md`（只记待处置缺陷）；③ 影响结论须过三要素（链路仍生效/目标存在/前置开关）并按三级措辞；④ 子代/检索数据只可引用 `[原文]` 级并抽验 ≥1 条 |
| 批量／多文件治理 | **试点放量打法** | ① 全量前先单样本 `--dry` 逐字节校验；② 3-5 代表文件试点（含 1 个最复杂文件）全绿才放量；③ 累计 ROLLBACK >20%（≤5 文件时 ≥2 即触发）整批终止倒序恢复；④ 7 防线绿灯逐文件缺一不可交付 |
| 重构／范式迁移 | **枚举对齐打法** | ① 改一处即 grep 全仓该模式调用点建「期望集合」基线；② 逐点对齐写法、缺漏即补，含操作意图维度（自动受约束/手动豁免须显式判定）；③ GATE 断言「总数==期望且旧范式残留=0」；④ 配对契约叠加三项核验 |
| DB／DDL／数据操作 | **先证后写打法** | ① DDL/批量 DML 先输出执行计划＋影响行数并确认，无人类输入默认取消；② 规划期预设 DB 备份点/回滚脚本，禁仅依赖 `.bak`；③ 多表写显式事务+rollback；④ 生成 SQL 必须实跑验证（`mysql-database.md`「SQL 动态构建验证铁律」）；⑤ 并发/重跑声明幂等与竞态防护 |
| 规则／文档维护 | **声明式打法** | ① 只写「须/禁止＋判据＋指针」，禁叙事/现状快照；② 主规则余量不足时禁增常驻内容（新内容落按需子规则＋挂载）；③ 外移/重组核对四种残留形态 0 违规（旧标题/旧指针/新旧混用/对称不一致）；④ 改后三断言回归；⑤ 新术语先登记术语表 |
| 脚本／工具链开发 | **落点判据打法** | ① 先判长期性再定目录：一次性→项目临时区（按项目约定定位），长期或被规则引用→项目脚本/门禁区，禁散落根/业务目录；② 复用既有脚本优先于新写；③ 遍历一律排除点目录（`.` 前缀通用判据，禁逐个点名）；④ CLI/配置禁硬编码本机绝对路径 |
| 部署／同步 | **包核对打法** | ① 改动按原相对路径复制进同步包，**包内只放本次任务改动文件**；② 收尾跑同步校验脚本 rc=0 才算收尾；③ "线上生效"结论前须确认服务器文件已更新（比对长度/特征串）；④ 部署/上线是用户决策，Agent 只备包并给上传后自查点 |
| 前端/模板/样式 | **取样→最小结构改动→三道校验** | ① 先取样原项目风格并逐行对齐；② 最小结构改动（不顺手重构 DOM，防布局连带崩）；③ 收尾三道校验（标签嵌套/元素可达/DOM 可见性＋移动断点 320/375/414/768）；④「好看/居中」类模糊词先过量化验收转换表 |

> **未命中兜底**：任务类型未命中上表任何行 ⇒ 按通用推理骨架（`agent-reasoning-patterns.md` 五段＋补强）＋阶段流执行，禁以「无对应打法行」跳过打法选择；命中多行时**叠加执行**。

⚠️ **边界护栏（L0，防"质疑需求"被误用为缩范围）**：「质疑需求」**只针对实现方式与步骤是否过度**——能否用更少步骤/更简方案达成**同一目标**；**严禁质疑用户已下达的业务目标本身**。任何删减主张须带证据 + 影响面并**交用户决断**，禁自行砍需求。

## 澄清策略分级（高 / 中 / 低，Step 2 引用）

SKILL.md Step 2 要求「业务规则 / 验收口径不明时，按澄清策略分级决定是否补问」。本节能级定义，执行时据此判定**问不问、问多少**，消除此前「分级」仅被引用无定义导致的决策点悬空。

### 三级判定标准

| 级别 | 触发条件（满足任一即归入该级） | 执行动作 |
| - | - | - |
| **高级** | ① 业务规则不明且错判有业务后果（如默认渠道 / 默认状态 / 计费口径写错会出脏数据）；② 涉及生产配置 / 数据库写入 / 权限 / 凭证 / 不可回滚操作；③ 多利益方视角未区分优先级；④ 验收口径直接决定"做对了没"却未给出 | **先问关键问题再执行**，最多 3 问；不假设、不默认。用户未回前不进入修改。**降级例外（仅限非 DDL 的代码改动）**：若该操作具备可靠回滚点（`.bak` / 事务 / 版本化——环境部署了 `.bak` 自动备份 hook 时由 hook 兜底，未部署时由 Agent 在改动前手工落 `.bak`）且影响可局部化，由高级降为**中级**——给默认假设 + 显式标注"如不符合请纠正"，允许先执行后纠，不阻塞（仍保留 SELF-AUDIT / 回滚兜底）。**破坏性操作（DDL / 删除 / 覆盖 / 批量写）一律不降级**，强制走 `delivery-assurance.md`「确认超时默认规则」的确认流，优先级高于本降级例外 |
| **中级** | ① 有合理默认但不同默认会导致实现差异（如返回 `0` / `0.0` / 抛异常、分页用游标 vs offset）；② 范围边界（是否连带改调用方）未确认；③ 性能 / 兼容性约束可推断但需对齐 | **先提案再纠**：给带权衡的推荐方案——列出候选方案 + 各自 trade-off + 推荐项 + 明确假设标注（"如不符合请纠正"），用户可在交付前纠正；不阻塞执行。仅对无候选方案的低歧义点给单一默认值 |
| **低级** | ① 纯信息查询 / 只读评估；② 目标明确、范围小、风险低、有最小验证闭环；③ 口径可无歧义从上下文推出 | **直接假设并继续**，无需单列确认；交付时说明假设即可 |

### 分级判定顺序

1. 先判**高级**：命中任意高级条件 → 进高级。
2. **高级降级检查**：高级命中且满足「**非 DDL 的代码改动** + 可逆（有 `.bak` / 事务 / 版本化回滚——hook 部署时自动兜底，未部署时改动前手工落 `.bak`）+ 影响局部化」→ **降为中级**（给默认 + 标注可纠正，不阻塞）；命中 DDL / 删除 / 覆盖 / 批量写 / 不可逆 / 影响全局 / 涉生产配置 / 涉凭证隐私 → 维持高级硬卡，并转 `delivery-assurance.md` 确认超时规则处理。
3. 否则判**中级**：命中任意中级条件 → 进中级，**先提案再纠**（带 trade-off 的推荐方案 + 假设标注）。
4. 否则 → **低级**：直接执行。

### 与意图三分法的关系

本分级只决定「澄清动作强度」，不替代意图三分法（信息查询 / 简单任务 / 复杂任务）对执行模式的判定。典型组合：
- 高级 + 复杂任务 → 先澄清后方案，双门槛。
- 中级 + 简单任务 → 给默认标注后快速通道执行。
- 低级 + 信息查询 → 直接回答，不写文件。

### 反模式（真实执行易踩）

- **澄清过度**：低级任务却反复追问 → 触发对话流异常边界「澄清过度」，进快速通道。
- **澄清不足**：高级条件已命中却未确认即执行 → 触发「澄清不足」，下调自主度补问。
- **伪分级**：把"想偷懒不问"包装成低级 → 凡涉库 / 权限 / 生产配置一律不得降为低级，安全闸门优先。
- **边界判定拍脑袋**：边界类判定（某内容是否敏感 / 某状态是否算完成 / 某操作是否属破坏性）只写抽象原则 → 改用**正反例枚举**：逐条给出「属于」与「不属于」的具体例子（如"饮食偏好与口味喜恶不是健康数据、可归档；裸缺省状态同样不是"），并把反例写进判据表；原则式规则抗误判能力弱于枚举。

### 保护型守卫 / 统一约束作用范围澄清（中级必问项）

凡设计「守卫 / 拦截 / 下限 / 配额 / 限流 / 防抖 / 锁」类约束逻辑，澄清与规划阶段须先确认**作用范围是否区分操作发起方**：

- 自动 / 批量 / 系统触发（按规则无差别扫描）与**手动 / 管理员明确选定**（强意图操作）是否应一视同仁？
- 命中即属**中级澄清必问项**（默认差异会致实现不同：一刀切拦截 vs 手动豁免）；须产出「约束适用边界 + 豁免边界」二值声明**并标注默认档**——按「澄清策略分级」中级口径**先提案再纠、不阻塞**（给默认 + 标注"如不符合请纠正"）；**仅当约束作用于不可逆 / 生产 / 凭证路径时才停下等确认**。

反模式：把「底层函数统一拦截」默认覆盖所有上层入口（手动 / 自动共用同一道闸），未评估「管理员明确操作」语义即替用户做默认选择 → 交付后暴露边界误判需返工。

## 批量修改 7 防线

批量修改（同操作影响 ≥ 3 文件或 ≥ 10 处修改点）时启用：

| 防线 | 动作 | 失败处置 |
| - | - | - |
| 1. 预检 | 全局 `lint`（含 PHPStan/ESLint 等），确保基线干净 | FAIL → 修复后重跑 |
| 2. 试点 | 取 3-5 个代表性文件，试改 | 任意 FAIL → 调整规则后重试，上限 2 次 |
| 3. 备份 | 改前 `cp → .bak`（自动保留最近 **10** 个历史版本 `.bak` / `.bak.1` … `.bak.9`），范围对齐批量计划 | 不可跳过 |
| 4. 批量执行 | 按计划逐文件执行 | 输出 `[OK/SKIP/ROLLBACK]` 逐文件日志 |
| 5. 后检 | 全局 `lint`，与前基线对比 | 新增问题 → 回退 |
| 6. MD5 校验 | 预期外变更文件输出 MD5 对比 | 标注差异来源 |
| 7. 回读确认 | 抽查 3-5 个文件，确认修改点正确 | 不一致 → 整批回退 |

回退规则：`ROLLBACK` 总量 > 20% → 整批回退。回退方式：倒序 `.bak` 恢复（`.bak` 为最新备份，数字越大越旧，最多保留 10 个版本）。

**脚本落点判据（先判长期性，再定目录）**：① **一次性/当次任务脚本**（批量修复、探针、验证桩、报告产物）→ 项目临时脚本区（按项目约定定位；该区可能被定期清理，不得承载任何长期依赖）；② **长期复用或被规则正文引用的脚本**（门禁校验、结果指标、结构断言）→ 项目脚本/门禁区（按项目约定定位，随项目留存、不入清理）。两类均禁散落项目根目录或业务目录。同类/后续任务优先调用既有脚本、不重复新写；复用通过 CLI 调用，不 `read_file` 拉源码进上下文。

**点目录一律排除（L1）**：任何遍历（`os.walk` / `glob` / `Get-ChildItem`）**目录名以 `.` 开头的一律跳过**——必须用通用前缀判据（`dirnames[:] = [d for d in dirnames if not d.startswith('.')]`），**禁逐个点名列 SKIP 名单**（漏列即漏排）。覆盖扫描/批量修复/交付复制/备份/图谱构建全部场景。

**小批量绝对值兜底**：改动文件数 ≤5 时百分比易失真（1/5=20% 即触发），用绝对值兜底——**ROLLBACK ≥2 即终止**，避免单次失败误判为批量崩盘。

## 清单化质量自审

代码交付前逐条自审（收口于 SELF-AUDIT·代码质量）：

```
☐ 异常处理完备（try-catch / 错误返回 / 边界条件）
☐ 硬编码常量已提取
☐ SQL / 外部输入已参数化
☐ 输出已转义（XSS / 模板引擎）
☐ 敏感信息不入日志/返回值
☐ 文件操作含路径白名单校验
☐ 超时/重试已设置上限
☐ 并发/竞态场景已处理
☐ 接口幂等性已保证（写操作）
☐ 注释与代码一致（无过期注释）
```

**技术债禁令**：

| 禁止 | 正确 |
| --- | --- |
| `if($a=func())` 赋值当判断 | 拆两行 |
| 返回 `array\|false` | 统一类型，空用 `[]`，异常 throw |
| `global $var` | 参数传入或依赖注入 |
| 注释代码留着 | .bak 备份后删除（无 Git!） |
| 参数 >5 个 | 封装对象/数组 |
| 循环内 `.` 拼接 | 压数组后 `implode()` |

**性能禁则**：

| 禁止 | 正确 |
| --- | --- |
| `SELECT *` | 显式列名 |
| 循环内查库 | 先批量预取 |
| 无 LIMIT 大结果集 | LIMIT+分页；全量扫描用游标 |
| N+1 查询 | 批量预取 |
| 裸 SQL / 裸拼模板 | 优先 CMS 内置 API；改配置后清缓存 |

**注释极简（L1，硬判据）**：

- **允许内容仅三类**：① 调用契约（参数/返回值/前置条件）② 非显然防御意图（为何必须这样写）③ 反直觉事实（读码看不出、改错即踩坑的约束）。
- **量化上限**：单处注释块 **≤2 行**；超限即判为叙事，须删减或迁移。
- **禁止**：复述代码已表达的内容；因果推导链（故/因此/⇒/另：）；实测回放（如「实测会 404」「跑出来是 X」）；方案比较与事故经过；他人文档的行号清单。
- **落点纪律**：非显然决策按约定写单行 `@decision`（含理由与撤销条件）；过程性叙述落规划文件的决策记录或 `errors/ERR-XXX.md`，**禁留在代码注释**。

## 防 AI 通病五戒（新增代码/重构时逐条对照）

AI 生成代码的高频通病，交付前必须自查是否踩中：

```
☐ 戒过度工程化：不为"未来可能"引入抽象/框架/设计模式；当前需求用最简单可维护方案，YAGNI
☐ 戒幽灵代码：不写无法触达的代码（死分支、未被调用的函数、永不成立的条件）；写完 grep 确认调用点存在
☐ 戒假注释：注释必须解释"为什么"而非复述代码本身；禁止"// 加1"式废话注释和过时注释
☐ 戒万能 try-catch：禁止吞异常的 catch 或 catch-all 掩盖真实错误；异常必须区分可恢复/不可恢复
☐ 戒无业务语义命名：变量/函数/类名必须表达业务含义（$totalPrice 而非 $a），禁止 a/b/c/tmp 式命名
```

## 防 AI 使用误区五因（协作姿态）

用户使用 AI 编程时最常见的五种误区，Agent 应主动纠偏而非迎合：

```
1. 一次喂超大上下文：期望一次完成所有事 → 改为分步迭代（见下「三重验证 + 分步迭代」）
2. 只贴报错不给上下文：缺少触发场景/输入/期望 → 主动索要复现信息
3. 未核对直接采用：AI 输出未经验证就合入 → 强制"改动点 + 验证证据"双展示
4. 反复小改碰运气：同一问题换措辞重试 → 先定位根因再一次性修复
5. 让 AI 背锅式兜底：期望 AI 替人做所有判断 → 关键决策仍由用户拍板，AI 只给候选与风险
```

### 三重验证 + 分步迭代工作流（对抗上述误区）

- **A. 上下文注入**：一次只给当前步骤所需的最小上下文（文件路径 + 目标 + 约束），不灌完整项目
- **B. 分步迭代**：复杂任务拆成 2-7 个原子步骤，每步完成即验证，不攒到最后一次交付
- **C. 三重验证**：每个改动点过三关——① 静态检查（语法/lint/类型）② 行为验证（实跑/单测/API 响应）③ 边界审查（异常/并发/安全触发面）
- **D. 反馈闭环**：验证失败 → 回到上一步修正 → 重新验证；连续失败 3 次暂停并输出差异分析

质量维度定义（验收时按此四维评分，缺一不可）：**性能**（耗时/内存/吞吐有可量化基线）、**安全**（触发面逐项过）、**可维护性**（单一职责/命名语义/无重复）、**测试**（关键路径有验证证据）。

## 架构一致性铁律（修改已有系统时强制）

修改大型/既有系统时，新代码必须与既有架构保持**同构一致**，禁止引入"局部新范式"：

```
☐ 范式唯一：既有是面向过程就继续面向过程，既有是 MVC 就按 MVC 落；不因个人偏好引入新模式
☐ 对称契约同源：同名操作（增删改查、导出导入、登录登出）的入参/出参/错误码定义必须同源复用，禁止各写一套
☐ 模块边界一致：新增代码放既有模块体系内，不新建孤立"万能工具"目录；依赖方向不逆流
☐ 半迁移 = 0：不允许"一半新一半旧"的过渡态留在交付里；迁移必须一次到位或明确标注为独立重构任务
☐ DDL 字段自愈表登记：改数据库表结构/加字段/字段长度或类型变更时，字段一律先登记项目自愈表（如 EmpireCMS 的 `$specs`/`$lenSpecs`）并配套安装 SQL 与后台长度校验；禁只改用点不登记——只改文件层漏数据层（表无该列时读侧取空值、写侧报 Unknown column，功能阻断）
```

> 判定基准：**以现有代码实际风格为规范**，而非以"我认为更好"的通用最佳实践；改样式先看周边代码怎么写的。

## 复用 vs 复制判定（重复代码出现时先判后动）

发现相似代码片段时，禁止直接复制粘贴或直接抽象，先走判定：

```
已有相似代码 → 判断差异度：
├─ 逻辑完全相同 → 提取公共函数/基类（复用），调用点统一替换
├─ 逻辑 70%+ 相同 → 参数化合并（差异点作为入参），保持单点维护
├─ 逻辑 < 70% 相同 → 保留独立实现，但命名/结构对齐既有风格
└─ 跨模块相似 → 若属同一领域契约，抽到公共层；若领域不同，不强行合并
```

> 复用优先级：**先复用既有工具函数 → 再参数化合并 → 最后才新写**；新写前必须说明为何不能复用。

## 覆盖完整性枚举闸门（Step 4 验证专用）

改动交付前，必须显式枚举"全部相关面"并逐项给出验证状态，禁止只验证单一路径：

### 5.1 对称性 / 覆盖枚举

```
☐ 对称操作全覆盖：改"导出"必须验证"导入"；改"新增"必须验证"编辑/删除/查看"同契约路径
☐ 数据形态全覆盖：空数据 / 单条 / 边界值 / 超大数据 / 非法输入逐项过
☐ 调用方全覆盖：改了函数签名，所有调用点（grep 确认）都要过编译/运行
☐ 分支全覆盖：if/else、switch 各分支都给出执行证据，不跳过 else/异常分支
```

### 5.2 交付前静态全量扫描

```
☐ 全量语法检查：改动的所有文件跑语法校验（如 php -l / node --check），不只是改动行
☐ 全量引用核验：grep 所有新增引用点（函数/变量/配置键），确认存在且签名一致
☐ 全量日志核验：运行期无新报错/警告（对比改动前后日志差异）
☐ 全量影响面核验：按 P1 依赖闭包逐文件确认无遗漏调用方
```

> 收口于 SELF-AUDIT·覆盖完整性：上述任一枚举项未给证据，SELF-AUDIT 不得全绿。

### 配对契约与迁移完整性核验（Step 4，防半迁移）

当改动属「旧范式→新范式」同构批量替换，或存在 set+get / 生产者-消费者对称契约（缓存键、函数签名、SQL、接口、模板标签）时，Step 4 除常规验证外**强制**三件事：

- **覆盖刚性**：验证须覆盖**每一个被改函数 / 分支 / 对称单元**，禁止只抽样已确认正确的单元（抽样命中正确单元 ≠ 其余单元正确）
- **配对闭环断言**：set+get 类改动每一处都须有「set 写入 key / 签名 == get 读取 key / 签名」的同源等式断言，且命中 + 未命中两条路径均须覆盖
- **迁移完整性 GATE**：改完后 grep 确认无旧范式片段与新范式在同一调用点混用、无旧范式残留（如 `remember` 与 `set` 混用、`<?` 与 `<?php` 混用、旧写法与新写法混用），残留 = 0 方准入交付

典型缺口形态：① 对称两端 key / 签名不一致；② 只抽样已正确单元而漏检其余单元；③ 同调用点新旧范式混用。任一条不满足 → 回 Step 3 补改后重走 Step 4，并在 SELF-AUDIT「迁移完整性」行如实标注。

### 移除/停用类改动的存在性锁（反向断言，L0）

> 定则：删除功能时**不得**随功能一起删除其护栏——须把断言反转为"该能力必须不存在"。

- **① 先证不存在**：删除/停用前须证明目标标识全仓 **0 命中**；检索须覆盖控制点与**动态调用**（`call_user_func` / 变量函数 / **前缀拼接式动态调用**，如 `'prefix_' . $var`），并注意 `grep` 输出被截断的风险。"无静态调用点" **不等于**可删除；判决 `NO-HIT`／`DEF-ONLY` 亦**不等于**可删除，仍须给功能归属判定。**典型形态**：① 字符串派发链（表单值→任务类型常量→进度步进变量→同名函数，零静态调用点）；② **固有盲区**＝DB/配置驱动的回调名（源码无字面量）七面全空仍不能证明可删 ⇒ 只能人工归属判定。
- **② 留反向断言**：改后须新增一条"该能力/标识**必须不存在**"的断言（`grep` 0 命中或断言脚本），并入回归；证据类型限「命令+输出」或「测试报告」。
- **③ 功能归属判定**：须给出结论——该能力由哪个入口在用、抑或确为历史残留；判定须带调用链证据，禁只凭"没人调用"下结论。
- **④ 桩捕获（L1）**：验证会删改系统状态的逻辑时，**须以桩捕获参数**（禁真跑）；桩无法覆盖的副作用改用隔离环境。
- **⑤ 改前核对目标（L1）**：删除/覆盖/替换前须先看目标本体——内容与任务描述不符、或并非本任务所建（他人/他批产物）⇒ **先报告再动作**，禁直接删改；范围外内容一律保全。动作后须说清「删/覆盖了什么、能否恢复」。
- **判据**：删除/停用类改动缺 ①②③④⑤ 任一项，阶段4 判不通过。

### 外移/重组专项强制项（追加，不改写上文）

第 ④ 种残留形态＝**旧指针**——引用目标**仍存在但已非权威源**（内容已外移/降级为摘要，指针未同步 ⇒ 悬空类与存在性类校验**全漏**）。凡本任务含内容外移/重组，须逐条核对**四种残留形态**（旧标题／旧指针／新旧混用／对称不一致）并留痕，**0 违规**方准入阶段4；核对手段＝① 步骤号校验脚本（有悬空回显）② 引用悬空清单 ③ `grep` 旧指针目标串全仓 **0 命中**。对被修正的权威行，**优先追加而非改写**。

### 方案—改动一致性与审查三问（交付前必过，L1）

**一致性核验**：把实际改动逐文件对照 plan 步骤勾选项与文件清单——**多改、少改都要解释**；顺手改出的无关文件一律回退或记入「待办」，不得混进本次交付（防"顺手改"污染范围）。

**变更重要性过滤（更新既有文档时判是否改正文，L1）**：文档/规则/plan/错误册/日迹的**已有内容**随事实变化时，先判**变更是否与该文档已关注点同层面**——同层面（职责/架构/约定/判据本身变化）→ 更新正文＋同步指针；不同层面（实现细节/行号漂移/局部措辞）→ **只更新指针，正文不动**；兜底约束：bug 修复、性能优化、重命名、格式调整、测试变更**不改正文**；目标文档已关注点不可辨 → 降级为「只更新指针」并在 plan 记明降级理由。**禁**把"只更新指针"当省事借口：同层面变更而只挪指针，视同漏改。

**审查三问（每问须给具体答案，打勾不算）**：

1. **接口兼容**：改了哪些公开接口（函数签名·API·数据结构·模板标签·SQL 列）？调用方是否**全部**适配？附 `grep` 证据。
2. **边界处理**：输入（空值·超长·负数·重复·并发）+ 输出（值域·错误码）+ 异常路径（依赖不可用·超时）——各有处理或显式标注「未测」。
3. **proper fix 还是 workaround**：若是 workaround ⇒ 写明为何不做 proper fix + 记入技术债（收尾「待办」）；若是 proper fix ⇒ 是否有更简洁实现、半年后别人能否看懂。

**范围外发现**：发现的技术债/隐患**记录并报告**（收尾「待办」或已知问题），**不越权重构**。

### 阶段4 回归基线（改码类，L1）

- **触发**：修 Bug / 重构（非纯新增功能）类交付。
- **要求**：除目标用例通过外，须跑**相邻功能回归**（被改函数的直接调用方 + 同模块既有入口），证据中附**失败清单**；清单为空亦须显式声明「已跑、0 失败」。
- **分工**：「覆盖刚性」管**被改单元**全覆盖；本条管**未被改的相邻功能**无新增破坏。
- **缺项判据**：无回归结论 → 阶段4 未通过（SELF-AUDIT 判不通过）。

### 阶段4 附加断言门禁（L0/L1）

⚠️ **跳转/回跳类终点断言（L0，防收尾漏检）**：凡改动涉及页面跳转、回跳、重定向或中转链（含由中间页/端点发起的回跳），E2E 除验副作用外**必须**断言跳转链**结束后**的状态，三项齐备：① **终点**——`location.href` 与 `document.title` 等于预期页面（不得停在中间页/错误页/404 页）；② **无异常提示**——页面文本不得含 `非法来源`/`FailHash`/`404`/`DbError`/`ErrorUrl` 等异常标识；③ **无循环**——静置 ≥2 倍跳转间隔后位置不再变化。**回跳目标审计**（与①配套，规划阶段即须确认）：由中间页发起的回跳，其目标必须为**无害页**（只读页/列表页/入口页），**禁止**指向会再次执行同一动作者；回跳目标所携带的来源校验参数须与目标页要求一致（GET 侧若校验来源 hash，则 `ehash` 与 `rhash` **缺一即失败**）；回跳目标为相对路径时，须按**发起回跳者所在目录**解析确认可达。**判据**：仅"副作用已发生"**不构成**跳转类改动的 E2E 通过；副作用正确 + 收尾异常（404／来源校验失败／循环）属漏检形态。

⚠️ **产出物身份断言（L0，防"假完成"）**：凡验证产出物（生成/下载/写入/返回/缓存的数据与文件），须断言其**就是本任务目标物**——以身份标识（ID/键/路径）与归属关系逐项对应，确认非同名物、非示例物、非旧物、非他处同型物；仅「存在/非空/格式正确/命令成功/退出码 0」**不构成**通过。产出物带目标参数的（查询条件/目标 ID/请求参数），断言须含参数 ↔ 产出物对应关系。**标识串/键值/摘要类产出物（校验码·配置键·哈希等）须逐字复核**——拆段核对，超长内容改抽样＋校验和，防转录敲错。

⚠️ **看不见的结果改用代理判据（L1，防"应该对了"式默认通过）**：渲染/图像/音频/PDF 等自身无法直接观测的产物，收尾前须**先显式声明观测手段**（文本线索／结构化 dump／日志特征／截图代理），据其给结论；观测手段不可得时如实申报观测缺口，禁硬造"看起来对"。

⚠️ **结论范围 ≤ 验证范围（L1，防单点外推）**：单点或单次观察不得外推为全类结论或规模断言——「一处通过」≠「同类全部通过」；「一处有守卫/校验」≠「其余同类同构已防护」。结论含「N 个/所有/均/无/全量」或数字范围时，须附枚举或全量实测口径（命令 + 输出），未覆盖部分显式标注；未实测的数字一律标注「估计」。

**不可达优先替身（L1）**：目标环境不可用（无浏览器/无网络/无依赖）时，**优先构造等价替身**（stub 依赖/合成输入/无头逻辑测试）完成验证并显式声明替身边界；「告警跳过」仅当替身亦不可构造。

**验证失败三向裁决（L1）**：断言失败先裁决『实现 bug ／ 测试(断言) bug ／ 期望(需求)不一致』三类——实测取证后分别处理（修码／改断言／改文档或问用户）；禁一律当实现 bug 修，亦禁一律改测试。

### 真人功能验证硬约束（L0，防静默损坏）

语法检查通过 / 纯函数断言 / 源码静态断言**均不担保功能正常**——静态层只验语法，运行时作用域缺失、依赖未加载、入口未接通只在真实调用暴露。

- 凡改动文件有 **UI / 后台 / HTTP 用户可达入口**，其验证**必须含真实驱动的功能验证**（真实入口 → 真实操作 → DOM / 行为断言），**禁止仅以 lint / 纯函数 / 源码静态断言替代**；
- 纯库函数无用户入口的，须以**真实调用路径**（CLI 打真实代码分支 / HTTP 请求打真实入口）驱动等价验证，仍禁止仅静态断言；
- 无真人功能验证证据 → SELF-AUDIT 判不通过。

### 回滚决策

| 范围 | 操作 |
| --- | --- |
| 单文件 | `.bak` 覆盖 → `php -l` 确认 → 重改 |
| 批量异常 | 倒序逐文件 `.bak` 恢复 → 整批重跑 assert |

## session_memory 标识（id）生成规则（Step 0 / Step 6 引用）

SKILL.md Step 1.1 Layer 2 读取 `{YYYYMMDD}/session_memory_{session-id}.jsonl`、Step 6 写入同名文件；首次会话无 session-id 时由 Step 0 探测阶段生成（见下生成规则），兜底读取取当日最大时间戳 jsonl。为避免跨会话恢复时找不到对应文件，本节能级统一 **`session-id` 的生成与存储约定**：

### 生成规则

- **格式**：`session-id` = `YYYYMMDD-HHmm`。
- **生成时机**：本次会话首次进入 **Step 0（新会话加载 / 探测阶段）** 即生成并写入当日 `daily.md` 顶部 `session-id: {YYYYMMDD-HHmm}` 行（唯一真相源）；若 daily.md 无此行（旧会话 / 首次），取当日目录下时间戳最大的 `session_memory_*.jsonl` 兜底（见下读取规则）。
- **存储**：写进当日 `daily.md` 顶部一行 `session-id: {YYYYMMDD-HHmm}`，作为唯一真相源。
- **读取**：Step 0 恢复时，先读 `{YYYYMMDD}/daily.md` 顶部的 `session-id` 行，再据该值定位 `session_memory_{session-id}.jsonl`；若 daily.md 无此行（旧会话 / 首次），则取当日目录下文件名时间戳最大的 `session_memory_*.jsonl`。

### 收敛要点

- 单日多会话：各自有独立 `session-id`，互不覆盖。
- 续做定位：用户说"继续"时，按 `daily.md` 记录的 `session-id` 精确恢复，不依赖猜测文件名。
- 无历史：探测失败 → 正常进入意图识别，不阻塞（与 Step 1.1 触发规则一致）。

## 安全闸门（Step 2 前置于修改阶段）

- 涉及生产配置、数据库写入、权限、凭证、隐私或不可回滚操作时，退出快速通道，先给方案和验证路径。
- 发现密钥、Token、账号、内部路径时，只说明风险和处理动作，不展开敏感值。
- 低风险可验证的编码任务不得因泛化安全理由拒绝。

**动作决策轴（决定"直接做"还是"先确认"）**：

- 决策轴＝**可逆性 × 影响对象**：可逆且源于本次请求的本地工作 → 直接做；破坏性 / 难逆 / 外发 / 影响共享系统 → 先确认。
- **许可请求是最后一步**：请求许可前先完成所有已授权且必要的工作，使提议的动作**具体可审**（先干完活再问"是否发布 / 是否合并 / 是否写外部系统"），禁活未干先问"要不要做"、禁反复请求已授权事项。
- 确需确认时显式说明**为什么需要**（哪条规则命中 / 缺哪项授权），禁只问"是否继续"。
- **被拒的工具调用＝用户拒绝** → 调整方案，禁原样重试或换等价措辞再试；拦截输出（hook / 审批）当作用户反馈，禁当噪声绕过。
- 授权只在声明范围内有效：一次批准不延伸到下一次；"以前批过""工具可用""自动放行"均不构成本轮授权。
- 「流逝的时间不是答案或批准」「沉默不等于同意」：无回复不等于获批，不得据此推进依赖项。

## 非 Git 文件操作安全协议

所有文件修改遵循：

1. **编辑前先读文件**：修改已有文件前必须先读取，确认上下文、编码和插入位置。
2. **优先局部补丁**：用最小范围局部 diff 修改，禁止无必要全文重写；发现未知改动不得覆盖、清空、回滚。
3. **中文与编码安全**：涉及中文、PHP、CMS 配置时，避免可能改变编码的 shell 写入方式。
4. **验证失败不交付**：测试、构建、lint 失败时先修复；连续失败时输出阻塞原因和下一步所需输入。

## 错误提示

失败时必须输出：发生了什么（一句话）、可能原因（1-3 个，标注已确认/待验证）、修复方向（最小动作）、风险提醒（涉生产/数据库/凭证时请求确认）、需用户提供什么（仅在缺输入时提出，格式"需 [角色] 提供 [具体输入]"）。禁止只输出"报错了/失败了"。

## 网络重试

临时超时/5xx 最多 2 次自动重试。写操作/扣费/发消息/4xx/权限失败/参数错误不自动重试。重试后仍失败时输出状态和下一步，不静默扩大执行范围。

## 对话流异常边界

| 失败模式 | 触发阈值 | 回退动作 |
| ------------ | ---------------------------------------------------------- | ------------------------------------ |
| 过度路由 | 加载子规则/reference >3 且任务为单文件修复或纯查询（本可用 Trivial Fix 快速通道直接完成） | 回意图三分法：单文件修复→Trivial Fix 直跑；纯查询→直接答；仅复杂任务保留多子规则加载 |
| 澄清不足 | 涉数据库/权限/生产配置且未确认即执行 | 下调自主度，补问关键问题（回到澄清策略分级高级） |
| 澄清过度 | 低风险任务连续追问 ≥ 3 次 | 进入快速通道，说明默认假设直接执行 |
| 快速通道误判 | 快速执行中发现跨模块(≥2)/数据库写入/批量(>10)/不可回滚 | 立即退出快速通道，输出方案和验证路径 |
| 理解委派 | 未输出目标/边界/验收口径即委派子任务 | 收回任务回到需求分析 |
| 跳过复核 | 子任务/子代理返回，或压缩摘要/记忆/旧审计结论未经回实码复核即写入文档/回复 | 对照验收口径复核；回实码 `read_file`/`grep` 复核每条代码引用（基于实码铁律） |
| 安全闸门失效 | 输出/日志/记忆中出现敏感值（凭证/内网IP/路径）或不可信输入未隔离即透传 | 立即脱敏+隔离不可信输入，恢复安全静态项检查，修正后再交付 |
| 拒绝误读 | 工具调用/权限/门禁被拒后原样重试（或换壳绕试） | 视为用户拒绝——调整方案（换路径/补信息/先问用户），禁原样重试；hook 拦截输出按用户反馈处置 |
| 以沉默或流逝时间当批准 | 无回复即推进依赖项 | 保持 pending 不推进；「流逝的时间不是答案或批准」「沉默不等于同意」 |
| 过度拒绝 | 合法且可验证任务被泛安全理由（如"涉生产"一刀切）阻断 | 复核澄清分级与降级例外，给出可验证的最小执行路径或明确需确认项 |
| 中途消息未分类 | 任务中途收到用户新消息（改需求/补充/问进度）未先定性即继续原路径 | 先判三类再动作——`override`（改需求）⇒ 旧工作作废留痕、按新需求重规划；`add`（补充）⇒ 并入当前计划、两件都做；`status`（问进度）⇒ 先答再续（按阶段导航只指路）。判错即返工 |

每次触发须标注：触发原因、回退动作、当前执行模式和剩余风险。

## 门禁资产只读（L0）

**例外与流程**（以"门禁更准/覆盖更全"为目标方可改，非"变绿"）：① 先出方案 + 影响范围（哪些门禁会松/紧）+ 撤销条件；② 用户确认；③ 改动本身按与业务码同等的验证办理，并按约定手工备份；④ 收尾报告「关键决策/验证证据」显式披露。

**判据**：触发点为"门禁结果"的资产改动一律违规；触发点为"门禁准确性/覆盖面"且经确认的改动合规。完整四权分离与防作弊红线见 `ai-coding-governance.md`「权责分离与防作弊红线」。
