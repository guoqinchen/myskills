# 正反手册（errors/ 负样本册 + success/ 正样本册）

> 收口于 Step 6 复盘沉淀阶段。本 reference 是随技能分发的**方法载体**：负样本防复发、正样本可升格、两册互哺、每个候选都有处置出口。
> 方法源自规则体系类的记忆纪律（写入纪律 / 踩坑记忆铁律）；**落点、文件名、索引格式与本技能 hooks 实码为准**（同源义务见 §0）——禁照抄其它项目路径导致文档与实现分裂。
> 定位升级：不只记「坑的结果」，更要把每条变成**决策失败样本**（错判点 / 正确判据 / 盲区），让诊断从「关键词命中」升级为「错判形状匹配」。

## 0. 落点口径（两态，禁混写）

| 维度 | 技能默认（跨 IDE） | 宿主权威（若有规则体系） | 对齐方式 |
|---|---|---|---|
| 记忆根 | `{PROJECT_ROOT}/.ai-memory/` | `.codebuddy/memory/` | 设 `AI_MEMORY_DIR` 指向宿主根即同源 |
| 反册索引 | `error_index.md`（**3 列**：`年/月/ERR-XXX ｜ 触发关键词 ｜ 标题`；根因分类等字段存单条、索引不重复列；≥6 列旧模板仍被 `parse_row` 兼容） | `errors/errors_index.md`（生成物） | 各自消费方为准，禁互换格式 |
| 正册索引 | `success_index.md`（技能自带 `scripts/success_index_gen.py` 生成物，禁手工追写） | `success/success_index.md` | 同上 |
| 单条目录 | `errors/<年>/<月>/ERR-XXX.md`（按首见日期归目录；扁平布局亦被 `ERR_FILE_RE` 识别） | 同左 | 分层推荐（两种布局均被守卫识别） |
| 命中统计键 | front-matter `hit_count` / `last_hit_at` / `low_quality_hit_count`（**由技能自带 `hooks/errors_recall_guard.py` 召回时自动记账**：判定成立即 `hit_count`+1、`last_hit_at` 刷新；仅泛用短词（boundary 通道）命中记 `low_quality_hit_count`；记账失败按条目号留痕） | 同左（宿主守卫自动递增） | 机器记账值禁手改；缺失按 0，禁以缺失推定复用 |
| 校验/生成脚本 | 技能自带（`scripts/`）：`err_next_id.py`（取号）/ `err_index_gen.py`·`success_index_gen.py`（索引生成）/ `err_id_dup_check.py`（编号与内容判重）/ `err_fields_check.py`·`success_fields_check.py`（存量校验）；判据经 `hooks/ledger_common.py` 单源 | 宿主若有同名工具则从宿主 | **禁双份**（同一判据两实现必漂移，ERR-226 族） |
| 归档形态 | front-matter `archive: true` ＋ 索引行移入「归档区」（**单条不移动目录**） | 同左 | 禁以移文件方式归档（丧失路径可定位性） |

- 记忆根解析顺序（实码 `hooks/ledger_common.py::memory_root` / `err_index_path`）：环境变量 `AI_MEMORY_DIR` → `PROJECT_ROOT/.ai-memory` → cwd 逐级上溯 → 脚本位置逐级上溯；全部未命中 ⇒ 静默放行（不阻断、不报错）。
- **同源义务**：本技能 hooks 若改记忆根 / 索引格式 / 字段名，本文档须**同批**改，否则文档假可达。
- **取号判据（防撞号）**：新建 `ERR-XXX` / `Plan/NN` 编号前，先**确定性遍历**取全局最大号 +1，禁凭会话记忆续号；遍历后须按**数值**排序取最大（禁字符串排序取末位——排序键与值域不匹配会取错），禁以检索「0 命中」断定「未登记」。

## 1. 闭环八环（全景）

| # | 环节 | 动作 | 不做的后果 |
|---|---|---|---|
| 1 | 动手前必查（含**重复犯错熔断**） | 任务/操作命中索引触发词 → 先检索定位单条再动手；**同一触发信号下连续 2 次出现同类失败 ⇒ 立即按环 2 定位读单条，禁第 3 次试同一种错法；达 3 次 → 按「不卡死」列 2-3 选项**（判据见 `execution-safety.md`「失败计数与升级」） | 同样的坑再踩一遍；熔断缺失 ⇒ 从零试错循环 |
| 2 | 确定性读取 | 单词检索 → 只读命中行 → 只读该单条；禁全量读 | 上下文爆炸；假阴性被误判「无此坑」 |
| 3 | 新坑即录 | 过成果门槛即落单（§2.7），禁等用户提醒 | 挣扎过程丢失，同坑复犯 |
| 4 | 取号唯一 | 遍历取最大号 +1；落盘后自检唯一性 | 撞号 → 定位读到**别人的坑** |
| 5 | 索引即入口 | 索引是唯一可检索入口，且**恒为生成物**（`scripts/err_index_gen.py` / `success_index_gen.py`，写侧守卫拦截手改） | 单条不可达＝白写 |
| 6 | 命中即复核 | 命中即验「正确做法」仍否成立；复现则 `Recurrence-Count` +1 | 条目静默失效，越常用的错内容越不被发现 |
| 7 | 归档评审 | 评审触发判断，不自动迁移；活跃坑不因条数迁出 | 册子膨胀，或活坑被条数阈值误迁 |
| 8 | 升格裁定 | Agent 自评裁定 + **处置出口**（可撤销、消音计数可见） | 候选每轮重复提示，退化为噪音 |

### 2.2 索引模板 `error_index.md`（3 列主模板，与 `errors_dup_guard.py::parse_row` 同源）

```markdown
# 错误索引（确定性定位：命中触发词 → 只读对应单条）

> 每行以 `年/月/` 前缀开头（直接定位 `errors/<年>/<月>/ERR-XXX.md`）；根因分类等字段存单条文件，索引不重复列。

2026/08/ERR-001 | 改 PHP 内嵌 JS 字符串拼接（window.open 参数）/php -l | php -l 只验 PHP 语法不验生成物，未闭合引号到浏览器才报 SyntaxError
2026/08/ERR-002 | ... | ...

## 归档区
2026/01/ERR-0XX | ... | ...（已归档：单条 front-matter `archive: true`，单条不移动目录）
```

- **3 列主模板**（`年/月/ERR-XXX ｜ 触发关键词 ｜ 标题`）为现行形态；≥6 列旧模板（`ERR-ID｜描述｜根因分类｜触发关键词｜日期｜Recurrence-Count`）仍被 `parse_row` 右侧定列兼容，但**禁同一文件混用两种列序**。
- **触发词可召回性（L1）**：触发关键词须含**至少一个代码中真实出现的字面词**（标识符 / 函数名 / 路径 / 后缀），与中文描述并列（`字面词/中文描述`）。实码口径：中文 ≥2 字走子串匹配、**可被机械召回**（`tokenize`）；纯描述型关键词仅支持人工检索，机械召回通道无法命中。**适用范围＝新增/修改条目的触发词，存量不回改**。
- 索引恒为**生成物**：单条是唯一数据源，禁手工编辑索引（写侧守卫拦截手改）；改单条后同批重跑 `scripts/err_index_gen.py`。

### 2.3 单条模板 `errors/ERR-XXX.md`

````markdown
---
err: ERR-XXX
year_month: YYYY/MM
type: 事实型
category: 工具行为
keywords: |-
  触发词1/触发词2/至少一个代码字面词
summary: |-
  一句话说清「什么场景 + 什么原因 + 什么后果」
hit_count: 0
last_hit_at: null
low_quality_hit_count: 0
---

# ERR-XXX: 一句话标题
- 类型: 事实型（取值 事实型 | 决策失败型，与 front-matter `type` 一致）
- 根因分类: 工具行为（取值见 §2.6，与 front-matter `category` 一致）
- 触发信号: 当要做 ___ 时
- 排查路径: ___（定位步骤，可附 `路径:行号` 证据，行号须真实存在）
- 根因: ___
- 错判点: ___（决策失败型必填：当时误信了哪个信号、忽略了哪个反例）
- 正确判据: ___（决策失败型必填：可证伪的判定标准）
- 盲区: ___（决策失败型必填：为什么之前没想到——认知缺口）
- 错误做法: ___（累计犯 N 次）
- 正确做法: ___
- 防范措施: ___
- 规避方案: ___
- 关联知识库: ___
- 来源: ___（任务名/日期，可选）
- Recurrence-Count: 1（同类触发累计次数；命中即复核驱动累加）
- Tasks: 1（跨不同任务数）
- First-Seen: YYYY-MM-DD
- Last-Seen: YYYY-MM-DD（仍成立 / 已修订：___）
- quality: 可用（可用 | 待补 | 不可用）
- utility: 现行（现行 | 待复核 | 已失效）
- Pattern-Key: ___（可选，稳定去重键，如 cms.routing.table_loaded）
````

**front-matter 键口径**：`year_month`＝首见日所在月（索引生成与归目录消费，**只取本单条自身 front-matter**，禁由「当前月份」推断）；`hit_count`/`last_hit_at`/`low_quality_hit_count` 为**命中统计键**——由技能自带 `hooks/errors_recall_guard.py` 召回判定成立时**自动记账**（先于展示预算截断；仅泛用短词命中记 `low_quality_hit_count`），**机器记账值禁手改**；缺失按 0 处理，禁以缺失推定复用。

**字段名与 hooks 解析同源（硬约束）**：`Recurrence-Count` / `Tasks` / `First-Seen` / `Last-Seen` 四字段须写「`名称: 值`」行内式，且**值前禁加括号**（`scripts/recurrence_promote.py::field` 按名称后紧跟冒号取值，`末核(Last-Seen):` 这类写法解析不到 → 升格评估静默失效）。日期值**后**可附全角括注说明。

**日期字段规范（新建必填，门禁硬拦）**：① 唯一允许写法＝上两行**行内式**（`- First-Seen: YYYY-MM-DD` / `- Last-Seen: YYYY-MM-DD（仍成立 / 已修订：___）`）；② 解析口径须单源（项目有统一日期解析实现则从之，禁调用方各写正则）；③ **存量补录**：原始记录确实缺失时写 `YYYY-MM-DD（占位：原始记录缺失）`——占位值不得用于归档判定 / utility 档位 / 30 天窗口判定；④ **新建禁占位**：新建条目日期必然可考（即当天），写占位属违规；⑤ 归目录月＝front-matter `year_month`（＝首见日所在月），`errors/<年>/<月>/` 与首见日须自洽。

### 2.4 决策失败型三栏（本册的核心升级）

错误分两类：①**事实型**——记根因与正确做法即可；②**决策失败型**——当时基于错误证据/忽略反例而判错。后者**必填**三栏：`错判点`（误信了什么信号）/ `正确判据`（可证伪的判定标准）/ `盲区`（为何没想到）。目的：下次比对的不是关键词，而是**错判形状**。**禁**把决策失败型误标为事实型以逃避三栏——那正是防「同样错判形状复发」的关键。

### 2.5 形态正反对照（逐字段，判据指针＝本技能 hooks 真实符号）

| 字段 | ✅ 正确形态 | ❌ 错误形态（后果） | 判据指针 |
|---|---|---|---|
| 索引文件名 | `error_index.md`（3 列主模板） | 行格式 3 列或 ≥6 列均被 `parse_row` 兼容，但禁同文件混用列序。⚠️ `errors_index.md`（复数名）**已被 `ledger_common._BOOKS` 双名支持**，不再静默失效；接入方若沿用复数名布局，`ledger_common` 按「根目录 → 册目录」顺序命中已存在者 | `hooks/ledger_common.py::_BOOKS['err']['indexes']`、`parse_row` |
| 触发关键词 | `不会加载/路由表`（中文与**代码字面词**并列，L1 可召回） | 纯中文描述 ⇒ 机械召回通道**不可达**（仅人工检索）；泛用中文短词（如「测试/新增」）→ 每次写盘大量无关命中，噪音高于收益 | `errors_recall_guard.py::tokenize`（中文 ≥2 字走子串匹配） |
| `category` | `业务逻辑（无长度保护）`（基础值合规，限定语入括注） | 枚举外自造值（如「代码行为」）；兜底类「其他」无括注 ⇒ `err_entry_guard.py` 写侧硬拦 | `err_entry_guard.py`＋`LC.load_categories`（真源＝本文档 §2.6；部署态降级留痕） |
| front-matter `keywords` | 必填五键之一，且含至少一个代码字面词 | 整键缺失 ⇒ `err_entry_guard.py` 写侧硬拦；纯中文描述 ⇒ **新建**条目被 `LC.code_tokens` 判据硬拦（存量编辑不拦，靠人读补） | `err_entry_guard.py::FM_KEYS_NEW`＋`LC.code_tokens`（写侧硬拦） |
| `type` | `事实型` / `决策失败型`，与正文类型行一致 | 自造值（如「判断失败型」）——`err_entry_guard.py::main` 写侧校验 front-matter `type`（`VALID_TYPES`），`err_fields_check.py:63` 存量校验，不合规即拦/判 FAIL | `hooks/err_entry_guard.py::main`、`scripts/err_fields_check.py` |
| 日期字段 | `- Last-Seen: 2026-10-11（仍成立）` | 行内式与标题式两种之外的自造名（如 `- 末次核验:`）→ 升格评估静默失效。⚠️ `末核(Last-Seen):` 的**括注形态已被 `date_parse` 的 `_PAREN` 支持**，不再解析不到 | `hooks/ledger_common.py::date_parse`、`value` |
| 写记忆路径 | `.ai-memory/`（或 `AI_MEMORY_DIR` 指向处） | 写 IDE 系统级记忆目录（不随项目迁移） | `errors_recall_guard.py::resolve_index_path` |
| 召回提示 | 命中后 `read_file` 对应单条复核 | 对提示视而不见 / 全量读 errors/ | `errors_recall_guard.py::MAX_HITS`（预算 3 条，防刷屏） |

### 2.6 根因分类（值域纪律）

| 类别 | 判定信号 | 易混边界（不属本类时归哪） |
|---|---|---|
| 框架行为假设 | 某 API 真实行为与预期不符，正确性靠想当然 | 同一语义两处实现不一致 → 业务逻辑 |
| 平台差异 | 编译期上限 / 内核实现 / 扩展版本约束 | 业务拼接方式触发 → 业务逻辑 |
| 配置冲突 | 同一开关多处可配，生效顺序决定行为 | 变量不存在 → 环境变量 |
| 缓存竞态 | 并发、时序、失效窗口导致的错读错写 | 单请求内顺序错乱 → 业务逻辑 |
| 工具行为 | IDE/CLI/钩子链路自身的**词法与执行行为**（参数解析、通道投递、编码转义、执行时序、文件系统行为） | 工具按设计工作、错在「使用方法/流程/决策」→ 方法论 |
| 业务逻辑 | 业务代码领域逻辑缺陷（删掉规则即不存在） | API 行为与预期不符 → 框架行为假设 |
| 安全沙箱 | 权限、转义、注入、凭证与信任边界 | 仅权限值写错 → 配置冲突 |
| 环境变量 | 换机 / 换 shell / 换 IDE 后行为改变 | 同环境稳定复现 → 按根因归类 |
| 方法论 | 做事方法缺陷：流程缺失 / 判据设计失当 / 验证取证缺陷 / 认知偏差 / 留痕与可观测性设计不足（工具/框架/平台均按其设计工作） | 工具真实语义与预期不符 → 工具行为；语言/框架语义 → 框架行为假设；随机器环境变化 → 环境变量 |
| 其他 | 前 9 类**逐条**不匹配（唯一兜底，须括注真实根因，如 `其他（流程缺失：评审环节无独立证据源）`） | 判不准先逐条排查前 9 类；无括注 ⇒ 项目侧写侧守卫硬拦 |

- **历史类映射**：旧「算法正确性」→ 业务逻辑（注明算法场景）；「设计取舍(taste)」→ 方法论（取舍失当属判据/认知层）。
- **type × category 正交（L1）**：`type` 判「是否决策失败」（存在本可证伪的判据而没验），`category` 判「根因落在哪一层」，二者**不可互相推导**；决策失败型缺失 `错判点/正确判据/盲区` 任一栏即不合规（§2.4）。
- **值域机械约束（L1）**：① 写入值须为表内**原值**，限定语放括注内（如 `业务逻辑（无长度保护）`），校验按剥括注后基础值比对；② **技能侧解析实现**＝`hooks/ledger_common.py`（`load_categories` / `load_success_types`），真源＝本文档 §2.6 / §3.2 表第一列——技能树内运行时**直接解析本文档**（单源禁双份，钩子目录禁放域值部署件）；`FALLBACK_CAT`（兜底类名）是唯一手工耦合点（表格结构不承载「哪行是兜底」），改表须同批改常量；钩子部署到本文档不可达的项目时值域校验**降级并留痕**（禁静默放行），项目自有值域表可经 `ERR_CATEGORY_RULES` 覆写；③ 引用行号验真若项目有统一实现则从之，禁各写一份。
- **新增类准入**：现有任一类无法容纳 + 附 ≥2 例存量条目及判定依据 + 先补判定信号与易混边界，**禁只加类名不加判据**；同批确认项目侧两脚本（若有）解析结果一致。
- **防垃圾桶化**：兜底类占比升高（建议阈值 10%）或单类吞并过半（60%）→ 触发「是新增类判据不足、还是既有类判据写错」的评审（`scripts/metrics_report.py` 单列 M6 兜底类占比、M7 最大分类桶占比，样本 ≥20 才告警；超阈值只触发评审，不构成放宽分类或新增类的理由）；**占比升高不是放宽分类的理由**。

### 2.7 新坑即录（成果门槛一票否决）

- **门槛一票否决**：任务取消 / 未解决 / 验证未通过 / 被拒或需大改返工 / 反复尝试未形成有效闭环 ⇒ **一律不录**（挣扎过程不是经验；「花了 40 分钟」不构成记录理由）。
- 过门槛后满足**任一**即写：①排查耗时 ≥40 分钟（交互 ≥4 轮视为接近）②≥4 轮交互 ③**导致返工的错误**（无论耗时，含工具/环境陷阱）。
- 长任务跨会话/可能被压缩的，须**每阶段末增量记录**，防压缩丢失。
- **写入路径动态定位（L1）**：写入/编辑含**年-月目录**或站点前缀的路径（`errors/<年>/<月>/ERR-XXX.md`、`success/<年>/<月>/SUC-XXX.md`、`Plan/*.md` 等）时，**须**先经 `search_file` 或 `os.walk` **动态定位**再拼文件名；`year_month` **只取单条自身 front-matter**，**禁**由「当前月份」推断；**禁**凭记忆拼目录名。写入侧守卫的失败信息**须指向真因**：目标路径不存在 ⇒ 报路径问题，**禁**报下游判据的结论。
- **入册质量门槛（与成果门槛 AND）**：①有明确复用价值 ②能帮后续更快定位/决策/实施/验证 ③含**非显然**信息 ④可抽象为项目无关的方法/模式/清单/决策规则。默认过滤四类：一次性操作记录、常识结论、与特定项目目录命名紧耦合的实现日志、只写结果不写推理的空壳摘要。**禁把"抽象"做成删内容**——具体内容保留为证据，被抽象的是结论的适用范围。
- **落盘判重（人工精判）**：对同分类相邻条目通读比对（触发词/标题/根因三点）——高度重复 → **合并**（留主体，被并条标「并入〈主条〉」）；部分重叠 → 保持独立 + 补边界说明与交叉引用。机械提示由 `errors_dup_guard` 出（`若确为新坑，请在描述中明确差异点后再建；若重复，更新既有 ERR 的 Recurrence-Count`），是否合并由人读单条精判。

### 2.8 触发与读取（确定性检索手法）

命中触发词 → 在索引上按触发词中的**单个词**检索（整串检索必漏）→ 只读命中行 → 仅 `read_file` 对应单条；**禁** `read_file` 整份索引、**禁**全量读 errors/。检索防假阴性：

1. `0 命中`须换更短/近义词复搜一次再下结论，`0 命中`≠`无此坑`。
2. 判「无命中」走 content 模式，禁 count 模式；检索禁传更具体的 glob（会被忽略规则剪枝成 0 命中）。
3. 工具报「空 / File is empty」而产物本应存在时，须用字节数或脚本解析取**独立事实源**再下结论。
4. 分档止损：命中不全 → 换单字词复搜，仍不全则读候选单条的「关联知识库」扩边；**全不命中 → 显式声明「本册无相关记录」**（禁把未记录的问题当作「已踩过」）。
5. 索引与单条不一致 → **停止消费**并重跑 `scripts/err_index_gen.py`，禁手工补索引行去「对齐」。

### 2.9 命中即复核（自动更正，不轮询）

每次命中并读取某条时，顺手复核「正确做法」是否仍成立（环境/工具/配置已变则可能失效）。失效或记错 → 当场修订该单条 + 刷新 `Last-Seen`；仍成立 → 仅刷 `Last-Seen`；本次**实际复现** → `Recurrence-Count` +1。无命中不轮询、不自动改。

- **两条结论冲突时禁粗暴二选一**（禁「删 A 留 B」式裁决）：先判是否**适用边界不同**（版本/平台/前提/触发条件），确属边界差异则改写为各自边界条件并交叉引用；仅当一条被证伪且无适用场景时才修订或合并。

### 2.10 归档评审（评审触发，不自动迁移）

- 触发＝①批次/长任务收尾的指标呈现（每次呈现即完成一次评审，0 条亦为结论）②单条 >500 行。
- 迁移仅限：`Last-Seen` 距今 >12 个月且仍成立、非环境级常驻坑；或连续 12 个月零复用且 `Recurrence-Count=1`。**活跃坑（12 个月内有末核）不因条数被迁出。**
- **归档形态**：单条 front-matter 置 `archive: true` ＋ 重跑 `scripts/err_index_gen.py` 使索引行归入「归档区」（禁手工追写索引行）；**单条不移动目录**（保路径可定位性）。禁以移文件方式归档。
- 「零复用」判据须谨慎：命中计数存在历史缺口时，「计数为 0」**不可单独**判死条目——须与「触发词是否含代码字面词」并置（**不可达**与**真正无用**是两回事）。

### 2.11 升格裁定（Agent 自评 + 处置出口）

- **硬规则（建议产出）**：`Recurrence-Count ≥ 3` 且 `Tasks ≥ 2` 且 30 天窗口内（实码 `scripts/ledger_judge.py::RECURRENCE_THRESHOLD / MIN_TASKS / WINDOW_DAYS`——判据单一实现，`recurrence_promote.py`（手动 CLI）与 `metrics_report.py`（R1 聚合）共用）。输出为**建议**，不自动改写规则文件。
- **裁定＝Agent 自评**：读单条原文 → 判「升 / 不升 / 待复核」→ 落**可撤销处置段**留痕（含理由与撤销方式）；禁以「等用户确认」挂起——挂起即每会话重复提示、退化为噪音。
- **升格质量门槛**：`quality=可用` 且 `utility=现行`；`Recurrence-Count` 高而 `utility=已失效` ⇒ 判失效进归档评审，**禁**以发生次数替代效用判定。
- **升格须写回滚点**：在条目内写明「若本条被证伪，回滚规则正文哪一处」——升格是把做法写进规则正文，只写失效条件不够，须能反向定位。
- **用户确认仅四类**：生产动作（部署/上线/DDL/发信/付款）、安全护栏放宽、门禁/评分资产改动、破坏性操作。禁把「Agent 自评」外推为「可自行改门禁资产」。
- **双档位（禁主观分）**：`quality` ∈ 可用|待补|不可用（长期属性）；`utility` ∈ 现行|待复核|已失效（每次评估）。量化口径：`Last-Seen` 标「已修订」⇒ 已失效；距今超 90 天或无 `Last-Seen` ⇒ 待复核；其余 ⇒ 现行。
- **存量回填口径**：回填两字段**须标来源**（`（存量初筛 YYYY-MM-DD）`）；`Recurrence-Count`／`Tasks` 的存量回填以「该条确已落单并被索引收录」为依据取 1，**禁**无依据补写；**禁**扩大写侧必填字段集——新增字段一律仅「存在时校验」，存量缺失不判不合规。
- **处置出口（消音契约）**：判「不升」须在该单条 append 处置段（`**处置：不升**（理由：___）`），删段即恢复候选；**候选必须有消音路径，且消音须计数可见，禁静默跳过——无出口的指标等同未完成**。

### 2.12 并发写入与保留（多会话/多进程同仓）

- 单条与索引由**创建者**维护；**禁**其它会话/进程批量删除单条、或以重建动作覆盖在途新建条目。
- 索引是生成物、只从落盘单条汇总：二者不一致只可能源于单条侧丢失 → 处置回单条侧，**禁**手工补/删索引行去「对齐」。
- 删除单条须同时满足成果门槛与创建者原则；**禁主动删除**（清理/去重/「看着过期」均不构成理由）。

## 3. 正样本册 success/（对称，补「只学负样本」缺口）

### 3.1 落点与模板

- `{记忆根}/success/success_index.md`（索引）+ `success/<年>/<月>/SUC-XXX.md`（单条，按首见日期归目录）；索引行格式与反册同源（`年/月/SUC-XXX ｜ 触发关键词 ｜ 标题`）。
- 单条字段：`类型` / `场景` / `做法` / `验证证据` / `Recurrence-Count`（复用次数，人工确认）/ `Tasks` / `Revisit if`（撤销条件）/ `utility`。

````markdown
---
suc: SUC-XXX
year_month: YYYY/MM
type: 方法型
keywords: |-
  触发词1/触发词2/至少一个代码字面词
summary: |-
  一句话说清「什么场景 + 什么做法 + 凭什么有效」
hit_count: 0
last_hit_at: null
low_quality_hit_count: 0
---

# SUC-XXX 一句话标题
- 类型: 方法型（环境型 | 工具型 | 方法型）
- 场景: 当要 ___ 时
- 做法: ①___ ②___（可直接照做的步骤，禁只写原则）
- 验证证据: YYYY-MM-DD <任务名> —— <命令输出 / 断言结果 / 回读结论>
- Recurrence-Count: 1
- Tasks: 1
- Revisit if: <什么条件变化即本条失效>
- utility: 现行
````

- **命中统计键（front-matter，禁手改机器记账值）**：`hit_count`（被召回次数，**由技能自带 `hooks/errors_recall_guard.py` 召回判定成立时自动递增**）/ `last_hit_at`（最近召回时间戳，`null`＝从未被召回）/ `low_quality_hit_count`（低质命中＝累计**会话数**：该条在这些会话里的召回**仅由泛用短词命中**——⚠️ **≠「命中后没解决问题」**，召回是字面匹配、无相关度分，故取「泛用词嫌疑」近似；中文词一律强命中不计入，ASCII 4~5 字母短词（如 `form`/`null`）计；仅作人工精修评审输入，**不触发任何自动降级/归档**）。分工：`hit_count`＝**被召回**（机器记），`Recurrence-Count`＝**实际复用**（人工确认），二者禁互相代替。
- **双消费判据**：`hit_count` 长期为 0 ⇒ **死触发词**（连续 3 个月召回 0 次 ⇒ 进精修/归档评审）；`low_quality_hit_count` 仅作精修评审输入。正册退役出口见 §3.4。
- **`utility` 档位（L1，与 ERR 侧对称）**：取值 `现行`/`待复核`/`已失效`；量化口径＝① `Revisit if` 已命中 ⇒ `已失效`；② 低质命中占比 `low_quality_hit_count/max(hit_count,1) ≥ 0.5` 且 `hit_count ≥ 10` ⇒ `待复核`；③ 其余 ⇒ `现行`。它解决「`Revisit if` 是自述性失效声明（写的时候未必准）」——`utility` 是**可被 `scripts/metrics_report.py`（M9-SUC 判据④）读取**的现行状态。存量不回写不判不合规；新建条目写侧校验以项目侧 entry guard 的既有键集为准。
- **Agent 例行裁定（口径①的执行动作）**：收尾/批次对「末核超期/无末核」或 `Revisit if` 疑似触发的条目**逐条** `read_file` 单条原文判 `Revisit if` 是否已命中——命中即把 `utility` 改为「已失效」＋单条 append `## 自动处置` 段（留原值＋理由＋撤销方式；删段即复原）。裁定主体＝**Agent 自评**（禁以「等用户确认」挂起）；**禁机械批量判**——`Revisit if` 是自然语言条件，须逐条读原文。

### 3.2 准入与类型判定

- **准入三条件（全满足才写，禁流水账）**：①已验证有效（有命令输出/断言/回读证据）②非显然 ③可复用。
- **类型三值互斥（禁骑墙）**：

| 类型 | 判定信号 | 易混边界（❌不属本类） |
|---|---|---|
| 环境型 | 结论依赖**本机/当前项目的运行环境约束**（换机、换 shell、换 IDE、换路径即变） | 换环境后仍成立 ⇒ 方法型；属某个工具自身的用法 ⇒ 工具型 |
| 工具型 | 结论依赖**某个具体工具/命令/钩子自身的行为**（该工具的语义、限制、调用方式） | 换成任意工具都成立 ⇒ 方法型；换机器才变 ⇒ 环境型 |
| 方法型 | 结论与机器、工具均无关，是**可迁移的做法/流程** | 依赖某工具特性 ⇒ 工具型 |

### 3.3 写入触发与消费点（对称义务，禁只写不读）

- **写入触发（满足任一即当场落单，禁攒到会话末）**：①收尾自检出现「试错后修正」且修正做法非显然 ②验证手段本身被证实有效且可复用 ③摸清一个环境/工具约束。落单后须**同批重建索引**（重跑 `scripts/success_index_gen.py`，禁手工追写索引行）——只写单条不建索引＝落了 memory 但不可达。**同批字段校验**：跑 `scripts/success_fields_check.py`（只读、退出码 0=PASS），与落单同批执行（errors 侧对应 `scripts/err_fields_check.py`，两册口径对称）。
- **路由对照**：踩坑 → `errors/`；已验证有效做法 → `success/`；铁律/偏好/环境 → `project_memory.md`。
- **消费点**：①**自动召回**——技能自带 `errors_recall_guard.py` 已支持**双册召回**（`[ERR-RECALL]` / `[SUC-RECALL]`，每册预算 3 条；单一召回通道，禁另建第二个提醒 hook）；②主动检索——规划/诊断阶段按任务关键词检索 `success_index.md`，命中只读单条。
- **命中即复核（正册口径）**：召回/检索命中且本次任务**实际套用**其做法时——成立 ⇒ 跨任务复用 `Recurrence-Count` +1（人工确认）；失效 / `Revisit if` 已触发 ⇒ 当场改 `utility` 并留处置段。`utility` 的首选写入时机＝调用时。

### 3.4 升格出口（口径与反册有意不同，不可互套）

- 判据＝`hit_count ≥ 3` 且 `Tasks ≥ 2`（**复用**驱动；实码 `scripts/recurrence_promote.py` 正册分支，`--success-index` 或自动发现 `success_index.md`）。反册看**复发**（RC≥3），正册看**复用**（hit≥3），两册阈值**不可互相套用**（实码 `scripts/recurrence_promote.py::SUC_HIT_THRESHOLD`）。
- **两册 `Tasks` 同名不同义**：反册是数字（跨任务数），正册可为**任务清单**（`Tasks: Plan/99, Plan/98`）——解析已内置 `ERR-235` 修法（`scripts/recurrence_promote.py::to_int`：数字式取整、清单式按分隔符计条目数）；直接取首个数字会把日期解析成年份，使 `tasks≥2` 被**错值蒙对**（假绿，E2E P2 用例守住）。
- **`hit_count` 缺失按 0 处理**（禁以缺失推定复用）；命中记账由项目侧召回 hook 承担（若其自动记账），技能侧以人工确认口径补记。
- 升格由 Agent 自评裁定（同 §2.11 纪律 + 处置出口 + 回滚点）；**用户确认仅四类**：生产动作 / 安全护栏放宽 / 门禁评分资产改动 / 破坏性操作——禁把「Agent 自评」外推为「可自行改门禁资产」。
- **退役处置出口**：`scripts/metrics_report.py` M9-SUC「零复用/已失效」候选裁定为**不退役**时，须在该 SUC 单条 append `## 退役处置（YYYY-MM-DD）` + `**处置：不退役**（理由：___）` ⇒ 指标读到即跳过（删段即恢复候选，同款可撤销契约、消音计数可见）；裁定为**退役** ⇒ 迁出扫描目录（项目既有归档区）并重建索引。**正册禁引用「`archive: true` 索引归档区」形态**（该形态正册未实现，反册专用）。

### 3.5 跨册反哺义务（补 ERR→SUC 缺口）

- 落反册单条时，若其「正确做法」已达正册准入判据（已验证/非显然/可复用，三条全满足）→ **须**同步落正册单条并**互相引用编号**；仅当正解依赖该坑的具体上下文（换场景即不成立）时免立，免立**须**在反册条目内注明「正解不独立成条」。
- 判定**不反哺**时须在该 ERR 单条 append `## 反哺处置（YYYY-MM-DD）` + `**处置：不反哺**（理由：___）` ⇒ `scripts/metrics_report.py` M10 后续读到即跳过（删段即恢复候选）。同一事件可同时命中两册。

## 4. 全局纪律

- **单一召回通道**：两册召回由一个守卫承担，禁另建第二个提醒类 hook。**豁免**：Pre 侧阻断型质量门禁（如写 Plan 前拦截的质量检查）内嵌召回判据属**门禁**非提醒通道，不构成第二召回通道。
- **指标设计纪律**：新增任何「列候选」的指标/门禁，必须自带处置出口（可消音、可撤销），消音须计数可见；**无出口的指标等同未完成**。
- **脱敏与禁忌**：禁记密码 / Token / API Key / 凭证 / 生产 IP / 内部域名；不经确认不写入；禁跨项目复用（每项目独立册）。
- **只读检索纪律**：主会话用 `read_file` 读单条；新增强条用 `write_to_file`；禁全量读 errors/ 或 success/。
- **角色边界**：本册由 Agent 依本方法维护；升格到项目规则正文、或修改门禁/评分资产，均属项目「用户确认四类」（生产动作 / 安全护栏放宽 / 门禁评分资产改动 / 破坏性操作），技能侧只产出**建议与证据**。
