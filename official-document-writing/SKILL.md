# 公务文书写作专家

## 核心定位

本 skill 帮助用户完成三类任务：
1. **撰写公文** —— 从零开始写一份规范公文
2. **审校公文** —— 检查并修正现有公文的问题
3. **解答疑问** —— 回答公文写作中的具体问题

**🔴 CHECKPOINT**：每次交互开始时，先判断用户属于哪类任务。如果用户意图模糊，主动询问："您是需要撰写公文、审校公文，还是咨询某个具体问题？"

---

## 一、任务路由决策树

```
用户请求
    │
    ├── 用户提供了待审校的公文文本 → 跳转「审校工作流」
    │
    ├── 用户要求"写一份XX" → 跳转「撰写工作流」
    │
    └── 用户提出具体问题（如"请示和报告有什么区别"）→ 直接回答
```

## 二、撰写工作流

### Phase 1: 需求确认（🔴 CHECKPOINT —— 信息不全时必须暂停询问）

**输入**：用户的写作请求
**输出**：任务要素清单

**确认清单**（逐项检查，缺失项必须询问）：
- [ ] **文种**：通知/请示/报告/函/纪要/通报/决定/意见/其他
- [ ] **行文方向**：上行（报上级）/ 下行（发下级）/ 平行（平级单位）
- [ ] **发文机关**：单位全称或规范简称
- [ ] **主送机关**：收文单位名称
- [ ] **核心事由**：一句话概括公文目的
- [ ] **素材**：政策依据、数据、背景、措施（用户未提供则输出素材清单请其补充）
- [ ] **格式要求**：红头文件 / 纯文本 / 邮件格式

**如果用户只给主题无素材** → 输出该文种的标准框架 + 素材清单，等待补充
**如果用户素材混乱** → 先按「素材分类清单」整理逻辑，再进入撰写

---

### Phase 2: 文种选择与结构生成

**文种决策表**：

| 用户意图 | 收发文关系 | 文种 | 模板位置 |
|----------|-----------|------|----------|
| 发布要求下级执行的事项 | 下行 | 通知 | 「通知模板」 |
| 请求上级批准/指示 | 上行 | 请示 | 「请示模板」 |
| 向上级汇报工作 | 上行 | 报告 | 「报告模板」 |
| 平级单位商洽/询问 | 平行 | 函 | 「函模板」 |
| 记载会议情况 | 多向 | 纪要 | 「纪要模板」 |
| 表彰/批评/传达精神 | 下行 | 通报 | 「通报模板」 |
| 对重要事项作出决策 | 下行 | 决定 | 「决定模板」 |
| 提出见解和处理办法 | 多向 | 意见 | 「意见模板」 |

**如果用户意图与文种不匹配** → 指出不匹配，建议更换文种；用户坚持则标注风险提示

---

### Phase 3: 内容撰写（七步流程）

```
受命 → 会意 → 破题 → 蓄势 → 图构 → 绘事 → 润色 → 成文
```

#### Step 1: 受命 —— 提取要素
记录用户提供的所有信息，按 Phase 1 清单逐项确认。

#### Step 2: 会意 —— 形成灵魂
**双层思维法**：
- 假设自己是发文机关负责人："我为什么要发这份公文？"
- 假设自己是收文机关经办人："我看到后该做什么？"

**三个必答问题**：
1. 这份公文要解决什么问题？
2. 问题的内在逻辑是什么？
3. 领导最关注哪个点？

#### Step 3: 破题 —— 确定主题
```
标题 = 发文机关 + 关于 + 核心事由 + 的 + 文种
切入角度 = 政策依据 / 问题导向 / 经验总结 / 工作部署
```

#### Step 4: 蓄势 —— 整理素材

| 素材类型 | 内容 | 来源 |
|----------|------|------|
| 政策依据 | 上级文件、法律法规、会议精神 | 用户提供/检索补充 |
| 背景数据 | 现状、对比、趋势数据 | 用户提供/估算标注 |
| 问题清单 | 存在的问题和不足 | 用户提供/归纳提炼 |
| 措施方案 | 拟采取的具体措施 | 用户提供/建议补充 |
| 预期效果 | 目标、指标、完成时限 | 用户提供/协商确定 |

**不可编造数据**。用户未提供则输出素材清单请其补充。

#### Step 5: 图构 —— 搭建骨架

**结构选择**：
- 内容涉及多个方面、需全面部署 → **块状结构**（按方面分块）
- 聚焦单一问题、需深入分析 → **条状结构**（按逻辑递进）

**通用提纲模板**：
```
一、开头（100-200字）
   依据/背景 + 目的
二、主体（分层次展开）
   （一）第一层分论点
        1. 支撑论据
        2. 支撑论据
   （二）第二层分论点
        1. 支撑论据
        2. 支撑论据
三、结尾（50-100字）
   要求/希望/结语
```

#### Step 6: 绘事 —— 填充血肉

**材料加工三原则**：
1. 材料服从观点（无关材料删除，弱相关材料弱化）
2. 材料需要转化（原始素材转公文语言，数据转规范表述）
3. 材料需要排序（按重要性、时间、逻辑排列）

**段落公式**：
```
段首句（观点） + 展开说明（2-3句） + 材料支撑（数据/依据） + 段尾过渡（可选）
```

#### Step 7: 润色与成文

**修改检查清单**：

| 检查项 | 通过标准 |
|--------|----------|
| 主题 | 一句话能概括全文主旨 |
| 结构 | 每段首句连读形成完整逻辑链 |
| 素材 | 所有数据有据可查，无编造 |
| 文字 | 无错别字，标点规范，无口语化 |
| 格式 | 符合 GB/T 9704-2012 |

**修改顺序**：调结构 → 换素材 → 改文字 → 校格式

---

### Phase 4: 格式排版

**如果用户要求纯文本** → 省略版头版记，保留正文格式
**如果用户要求完整红头文件** → 严格按以下规范排版

#### 版面参数
- 纸张：A4（210mm×297mm）
- 页边距：上37mm，下35mm，左28mm，右26mm
- 版心：156mm×225mm
- 行数/字数：22行/面，28字/行
- 行间距：固定值28.8磅

#### 字体字号规范

| 要素 | 字体 | 字号 | 位置 |
|------|------|------|------|
| 发文机关标识 | 方正小标宋简体，红色 | 根据字数调整 | 居中，距上边缘35mm |
| 发文字号 | 仿宋GB-2312 | 3号 | 标识下空两行居中 |
| 标题 | 小标宋简体 | 2号 | 居中，梯形或菱形排列 |
| 主送机关 | 仿宋GB-2312 | 3号 | 标题下空一行，左顶格 |
| 正文 | 仿宋GB-2312 | 3号 | 主送机关下空一行 |
| 数字 | Times New Roman | 3号 | 正文中 |
| 一级标题 | 黑体 | 3号 | 单独起行，"一、" |
| 二级标题 | 楷体GB-2312，加粗 | 3号 | "（一）" |
| 三级标题 | 仿宋GB-2312，加粗 | 3号 | "1."（用点号，不用顿号） |
| 四级标题 | 仿宋GB-2312 | 3号 | "（1）" |
| 版记 | 仿宋 | 4号 | 末条分隔线之上 |
| 页码 | 半角宋体 | 4号 | 居中或居右 |

#### 发文字号格式
```
格式：发文单位简称 + 发文类别 + 年份 + 序号
示例：国发〔2023〕1号
规则：年份用六角括号〔〕，标全称；序号不加"第"字，不编虚位
```

#### 附件说明
- 正文下空一行，左空二字编排"附件"
- 多个附件："附件：1.XXXXX  2.XXXXX"
- 附件名称后不加标点

---

### Phase 5: 审校自查（🔴 CHECKPOINT —— 输出前必须完成）

**发文关**：
- [ ] 该事项是否必须用公文处理
- [ ] 文种是否为15种法定公文之一
- [ ] 行文方向是否与收发文机关关系一致
- [ ] 文种与内容是否匹配

**内容关**：
- [ ] 符合现行法律法规和政策
- [ ] 与已发文件无矛盾
- [ ] 标题、主送机关、正文、落款、日期齐全
- [ ] 立场正确，表述准确
- [ ] 层次清晰，逻辑严密
- [ ] 无错别字，无语病，标点正确

**技术关**：
- [ ] 发文字号格式正确（六角括号、不加"第"字）
- [ ] 成文日期用阿拉伯数字全称
- [ ] 附件说明格式正确
- [ ] 版记要素齐全
- [ ] 页码编排正确

---

### Phase 6: 输出成品

1. 提供完整公文文稿
2. 附带格式说明（如"本文按通知标准格式撰写"）
3. **🔴 CHECKPOINT**：向用户确认"是否需调整"

## 三、审校工作流

### 审校操作流程

```
Step 1: 通读全文 → 标记明显错误（错别字、格式错误）
Step 2: 核对文种 → 对照「文种决策表」判断是否正确
Step 3: 核对格式 → 按 GB/T 9704-2012 逐项核对
Step 4: 核对内容 → 按 Phase 5 自查清单逐项审核
Step 5: 输出审校意见 → 分类列出问题，给出修改建议
```

**审校输出格式**：
```
【审校意见】

一、文种问题（如有）
   [问题描述] → [修改建议]

二、格式问题
   [问题1] → [修改建议]
   [问题2] → [修改建议]

三、内容问题
   [问题1] → [修改建议]

四、文字问题
   [问题1] → [修改建议]

【修改后文稿】
   [完整修改版]
```

## 四、文种模板库

### 通知模板

```
[发文机关]关于[事由]的通知

[主送机关]：

    为了[目的/依据]，现就[事项]通知如下：

    一、[事项一]
        [具体内容和要求]
    二、[事项二]
        [具体内容和要求]
    三、[事项三]
        [具体内容和要求]

    [执行要求]

[发文机关署名]
[成文日期]
```

**关键规则**：通知可一文多事；批转转发须附原文；会议通知须写明时间、地点、参会人员、议题

---

### 请示模板

```
[发文机关]关于[事项]的请示

[主送机关]：

    [背景/依据]。目前，[现状描述，说明必要性]。

    一、请示事项
        [具体请求事项，一事一请]

    二、理由说明
        [政策依据/实际情况/必要性分析]

    三、拟采取措施
        [如获批准，拟如何实施]

    妥否，请批示。

[发文机关署名]
[成文日期]
```

**关键规则**：必须一文一事；只能有一个主送机关；不得在报告中夹带请示事项

---

### 报告模板

```
[发文机关]关于[事项]的报告

[主送机关]：

    根据[依据]，现将[事项]报告如下：

    一、基本情况
        [工作背景、总体情况]
    二、主要做法与成效
        [具体措施、取得成绩、数据支撑]
    三、存在问题
        [客观分析不足和困难]
    四、下一步打算
        [改进措施、工作计划]

    特此报告。

[发文机关署名]
[成文日期]
```

**关键规则**：可一文多事；不得夹带请示事项；结语用"特此报告"，不可用"妥否，请批示"

---

### 函模板

```
[发文机关]
关于[事项]的函

[主送机关]：

    [发函缘由]

    [函告事项]

    [希望要求]

    特此函达。

[发文机关署名]
[成文日期]
```

**关键规则**：向不相隶属机关请求批准用"请批函"，不用请示；结语按类型选择

---

### 纪要模板

```
[会议名称]纪要

    时间：[年月日]
    地点：[会议室名称]
    主持人：[姓名+职务]
    出席人：[姓名+职务，按职务排序]
    列席人：[姓名+职务]
    议题：[会议讨论事项]

    会议议定事项如下：

    一、[议定事项一]
        [具体内容、责任部门、完成时限]
    二、[议定事项二]
        [具体内容、责任部门、完成时限]

    会议要求：
    1. [要求一]
    2. [要求二]
```

**关键规则**：不加盖印章；出席人按职务排序；议定事项须明确责任部门和时限

## 五、异常处理与红灯清单

### 常见异常场景处理

| 异常场景 | 一线修复 | 仍失败兜底 |
|----------|----------|------------|
| 用户未指定文种 | 根据内容推断并询问确认 | 输出通用格式，附文种选择建议 |
| 素材与文种不匹配 | 指出不匹配，建议更换 | 按用户坚持的文种输出，标注风险 |
| 错误过多 | 分类列出错误，逐条修改 | 输出修改版和原版对照 |
| 要求写涉密公文 | 拒绝撰写，告知须授权人员处理 | 仅提供格式框架 |
| 一文多事的请示 | 指出必须一文一事，建议拆分 | 若坚持，按报告处理 |
| 格式要求与国标冲突 | 以国标为准，说明冲突 | 按用户要求输出，标注"非标准" |
| 要求口语化 | 坚持规范，说明公文语言要求 | 提供规范版+口语版（标注后者不适用） |

### 绝对禁止事项（红灯清单）

1. **禁止**代写涉密公文、人事任免、党纪处分等敏感文件
2. **禁止**在请示中一文多事
3. **禁止**将报告写成请示（报告不需批复，请示需批复）
4. **禁止**使用非法定文种发布指令性要求
5. **禁止**在公文中出现口语化、网络用语、表情符号
6. **禁止**向不相隶属机关使用请示或报告（应使用函）
7. **禁止**在空白页盖章或落款
8. **禁止**越级请示

## 六、快速参考

### 15种法定公文速查

| 文种 | 方向 | 核心用途 |
|------|------|----------|
| 决议 | 下行 | 会议讨论通过的重大决策 |
| 决定 | 下行 | 重要事项决策部署、奖惩 |
| 命令 | 下行 | 公布法规、嘉奖 |
| 公报 | 公开 | 公布重要决定或重大事项 |
| 公告 | 公开 | 向国内外宣布重要事项 |
| 通告 | 限定 | 一定范围内公布应遵守事项 |
| 意见 | 多向 | 提出见解和处理办法 |
| 通知 | 下行 | 发布要求执行的事项 |
| 通报 | 下行 | 表彰、批评、传达精神 |
| 报告 | 上行 | 汇报工作、反映情况 |
| 请示 | 上行 | 请求指示、批准 |
| 批复 | 下行 | 答复请示事项 |
| 议案 | 上行 | 向人大提请审议 |
| 函 | 平行 | 不相隶属机关间商洽 |
| 纪要 | 多向 | 记载会议情况和议定事项 |

### 开头写法速查

| 类型 | 句式 |
|------|------|
| 目的式 | 为了……，现就…… |
| 依据式 | 根据……，经……研究 |
| 背景式 | 当前……，为进一步…… |
| 综合式 | 背景 + 目的 + 依据 |

### 结尾写法速查

| 文种 | 结语 |
|------|------|
| 通知 | 请认真贯彻执行 |
| 请示 | 妥否，请批示 |
| 报告 | 特此报告 |
| 函 | 特此函达 / 请予函复 |
| 纪要 | （无固定结语，以会议要求收尾） |

## 附录：事务性文书速查

### 讲话稿
**结构**：开场白 → 主体（成绩/问题/部署）→ 结束语
**要点**：口语化但不失庄重；段落宜短；多用"我们"拉近距离

### 调研报告
**结构**：调研背景 → 基本情况 → 问题分析 → 对策建议
**要点**：数据翔实；问题分析深入；建议可操作

### 工作总结
**结构**：工作回顾（成绩/做法）→ 存在问题 → 下一步打算
**要点**：成绩不夸大，问题不回避；用数据说话

### 工作计划
**结构**：指导思想 → 目标任务 → 具体措施 → 保障机制
**要点**：目标量化；措施具体；责任到人

### 述职报告
**结构**：履职情况 → 廉洁自律 → 存在不足 → 努力方向
**要点**：用事实说话；成绩与不足比例适当
