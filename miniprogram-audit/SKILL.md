# 小程序全量审计工作流（跳转 · 运行 · 留存）

适用于「功能看起来都做了，但说不清有没有人用 / 留存怎么样」的排查场景。产出的是**可复现的证据**，不是感觉。

## 何时用

- 想量化「功能使用率 / 留存率」但项目没有埋点
- 怀疑某些页/功能用户根本走不到（可达性 & 入口深度）
- 改过导航或路由参数后要确认没断链
- 要验收「首次使用体验」（几步入正题、哪里卡）

## 五段静态审计（逐段落文件，只读）

### ① 跳转图：可达性 × 入口深度

扫描全部 `wx.(navigateTo|redirectTo|reLaunch|switchTab)({ url: '/pages/...' })`，加上自定义 tabBar 的互跳边，构有向图后：

- **页面 → 入边数 + 从启动页 BFS 最少步数**（步数 = 曝光度的量化依据；深度 ≥3 的功能自然触达低）
- 目标不在 `app.json.pages` → 非法目标
- 入边为 0 / 步数不可达 → 孤岛页

```js
// ⚠️ 只匹配字面量 url 会漏掉「字符串拼接 / 模板字符串」形态，实测某项目 47 个调用点漏 15 个（32%）。
//    后果很隐蔽：漏掉的调用点不会进图，于是 ②「读了没人传」会大量假阳
//    （如 `'/pages/task/task?date=' + d + '&slot=' + s` 被漏 → 误报「slot 无人传」）。
// 正确做法：捕获 url 的**整个表达式**，再从中抽目标页与参数键。
const NAV_RE = /wx\.(navigateTo|redirectTo|reLaunch|switchTab)\(\s*\{[\s\S]{0,240}?url\s*:\s*([\s\S]{0,220}?)(?=,\s*[A-Za-z_$][\w$]*\s*:|\}\s*\))/g;
const PAGE_IN_EXPR = /['"`](\/pages\/[a-z0-9-]+\/[a-z0-9-]+)/i;   // 抽目标页
const KEY_IN_EXPR  = /[?&]([A-Za-z_]\w*)=/g;                      // 抽参数键（字面量与拼接通吃）
// 目标页确实无法静态判定时（如 tab-bar 的 ROUTES[key]）→ **显式列出来**，不要静默丢边。
```

**要点**：`pages/<x>/modules/*.js`（以及 `pages/<x>/*-data.js` 等辅助文件）里的跳转要**归属到宿主页面**——
别把归属写成只认某个页面的分支；按 `^pages/([^/]+)/` 取目录名归到 `pages/<x>/<x>` 即可
（否则来源页名错乱，setup 等有 modules 的页面会被漏掉）。自定义组件（tabBar）的跳转要单独展开成 tab 互跳边。

### ② 入参契约：传了 vs 读了

汇总每个目标页被携带的 query 参数，对比该页 `onLoad` 实际读取的键：

- 「传了没人读」→ 死参数（多为重构残留）
- 「读了没人传」→ 断链（或纯内部路径）

**必须支持别名**，否则大量假阳：

```js
// onLoad 里常见：const opt = options || {}; opt.type
const aliasRe = /([A-Za-z_]\w*)\s*=\s*options\b/g;   // 先把别名收集起来再匹配 ALIAS.key
```

### ③ 留存埋点接线率（找死代码）

对埋点/推送类模块（如 `utils/retention.js` / `utils/reminder.js`），列出 `module.exports` 的每个键，统计**生产代码**（pages/components/utils/app，排除模块自身）里的消费点数 → 0 即死代码。

典型结论形态：

```
retention.js 导出 7 项 → 存活 1 项（14%）
  ✘ track          消费点 0   ← 全链路 0 埋点，数据从未写入
  ✘ funnelStage    消费点 0
  ✔ weeklySummary  消费点 1   pages/stat/stat.js
```

**关键追问**：埋点函数依赖的画像字段（`setupAt` / `firstFillAt` …）**有没有写入点**？只接调用不写字段，函数也恒返回初始态。一并 grep 这些字段名。

### ④ 渲染缺陷扫描：`this.data.X =` 直接赋值

官方口径：直接改 `this.data` **不下发视图层**。扫描所有直接赋值，判定该键是否在**同一归属页面**（页面本体 + 其 modules）的 setData 中被下发：

- 无任何下发 → 高风险（界面永不更新）
- 有下发 → 需人工确认该路径是否覆盖

**必须按归属页面聚合**（模块里直接改、由页面 `refresh()` patch 下发是正确模式），否则假阳一堆。

### ⑤ 本地兜底 / 后门：客户端可控的降级路径（资损类，优先查）

**判据只有一条：这个降级/兜底路径的「触发条件」由谁掌握？**

| 触发条件 | 例子 | 判定 |
|---|---|---|
| **客户端可控** | 「云函数调用失败 → 回落本地静态码表」 | 🚨 **白嫖路径**：断网/拦截/环境未配即可命中 |
| 客户端可控 | 「环境判定失效 → 仍允许调试后门」 | 🚨 同上，`isRelease()` 挡不住环境判定异常 |
| 服务端掌握 | 「服务端校验不通过 → 拒绝」 | 安全 |

**为什么 `isRelease()` 这类门禁救不了**：它只挡住「解包后**直接查表**」，
挡不住「**让云调用失败**」。两者的差别就是「能不能白嫖」。

**扫描做法**：
```bash
# 1. 找前端是否持有「可直接授予权益的数据」——命中即高危
grep -rn "grant\|pro_buyout\|proExpire\|永久\|买断" --include=*.js pages utils data
# 2. 找降级分支：catch / fail 回调 / 通道不可用 之后是不是「给了东西」而不是「拒绝了」
grep -rn "fallback\|兜底\|回落\|降级\|NO_CLOUD\|CLOUD_FAIL" --include=*.js pages utils
# 3. 硬编码可疑串（'666' / 'test' / 'admin' / 'vip'）出现在码表/白名单里
grep -rniE "'(666|test|admin|vip|master)'" --include=*.js .
```

**确认「兜底真的被用上了」的证据口径（不看日志）**：
- 兜底一旦命中，**云端不会留下任何痕迹**。所以要用「云端应有的记录数 = 0」来反推：
  例：`bk_cdk_attempts` 在 `INVALID`/`EXPIRED` 时都会落库 → **Count=0 ⇒ 云端从未被调用过** ⇒
  「本地码可用」是兜底在服务，不是云通道在服务。
- 推论：**用兜底里的码自测，测不到云通道**（它永远走本地路径）。验收必须用真实凭据。

**修法**：删掉兜底本身（连同它依赖的码表/查表函数/本地记账），
而不是把门禁写得更严 —— 只要降级路径存在，就总有办法让它被命中。
删完**必须补执行级护栏**：桩环境真跑一遍，断言「任何失败场景下只拒绝、不改本地权益」。

报出这条后，顺手检查 `data/` 与 `utils/` 里是否还留有**只被兜底引用的静态清单**（删干净）。

## 动态审计：首用轨迹模拟

用**真实页面代码 + 存储桩**驱动整条链路，而不是断言单个函数。

```js
// 1) 冻结时钟（结果可复现；挑一个让关键门槛成立的时刻，如晚 20:00 让当日块"到点可打卡"）
const RealDate = Date;
class FrozenDate extends RealDate {
  constructor(...a) { if (!a.length) return super(FROZEN.getTime()); return super(...a); }
  static now() { return FROZEN.getTime(); }
}
global.Date = FrozenDate;

// 2) 存储桩 + 导航日志
global.wx = { setStorageSync, getStorageSync, showToast, showModal(o){o.success&&o.success({confirm:true})},
              navigateTo:o=>nav.push({api:'navigateTo',url:o.url}), /* redirectTo / reLaunch 同理 */ ... };

// 3) 页面装载：捕获 global.Page 的配置，构造带「逻辑层 + 渲染层」双模型的 page 实例
// 4) 载入真实 app.js（global.App 捕获后 bind，复用 sync/currentExam 等）
```

**页面实例必须双模型**：

```js
function mkPage(cfg) {
  const page = { data: clone(cfg.data) };
  page.render = clone(cfg.data);                 // 视图层：只随 setData 更新
  Object.keys(cfg).forEach(k => {                // 非函数属性（如 STEP_TITLES）也要带上
    if (k === 'data') return;
    page[k] = typeof cfg[k] === 'function' ? cfg[k].bind(page) : cfg[k];
  });
  page.setData = p => Object.keys(p).forEach(k => { apply(page.data,k,p[k]); apply(page.render,k,p[k]); });
  return page;
}
```

**断言分两级**（很重要）：
- `expect(...)` —— 链路硬闸，断链即 fail（用于回归门禁）
- `info(...)` —— 非阻塞发现（埋点未接、默认值有风险等设计缺口），记入 findings 而非 fail

**计数指标**：用户主动点击次数（`tap()` 计数）、链路断点、首个价值达成点、各阶段产物（落库条数/成就数）。**只统计"用户主动点击"**，系统自动跳转不计。

## 云侧结构审计（云函数 + 云数据库）

适用范围：用微信云开发（`cloudfunctions/` + 云数据库）的小程序。**这一层最容易长期无人校验**——页面逻辑有人测，云函数结构常常一个回归目标都挂不上。

**先做一个自检**：`cloudfunctions/` 下有 N 个函数，`tools/run-all.js` 里有几个目标碰它们？如果一个都没有，那多半已经躺着缺口。真实样例：8 个云函数里 7 个有 `config.json`，唯独搬运最大 payload 的那个没有 —— 微信云函数**未声明 `timeout` 时用默认 3 秒**，于是它成了唯一在吃 3 秒超时的函数，而报错只以「云调用失败」这种无信息量的形式浮上来。

**七项体检**（写成 `tools/check-<云相关>.js` 并进回归，别靠人肉看）：

| 项 | 判据 | 不查会怎样 |
|---|---|---|
| 三件套 | 每个函数必须有 `index.js` / `package.json` / `config.json`，依赖含 `wx-server-sdk` | 缺 `config.json` = 吃默认 3s 超时（重活函数必然超时） |
| 配置契约 | `config.json` **必须显式声明** `timeout`；`triggers` 必须仍在；`permissions.openapi` 覆盖实际调用的接口 | 改 timeout 时顺手删掉 `triggers` → 定时任务静默失效；缺 openapi → 运行期「no permission」 |
| `lib/` 副本完整 | `index.js` 里每个 `require('./lib/X.js')` 的文件都要存在 | 完整部署漏 `lib/` → `-504002 Cannot find module`，而函数状态仍显示 Active |
| **集合双向一致** | 代码里的集合名（`COLL_* = 'bk_*'` 与 `collection('bk_*')`）与文档表格集合**完全相等**（双向集合差为空） | 这一条能同时抓两类错：**文档多登记**（把本机存储键当云集合）与**代码漏登记**（上线漏建集合） |
| 调用方存在 | 前端 `FN_*` 常量指向的云函数都真实存在 | 发版后才在真机报「云函数不存在」 |
| 函数目录已登记 | 新增函数不登记进脚本的期望清单直接 FAIL | 把口头约定变成契约，防止新函数无护栏 |
| **前端零直连云数据库** | `app.js` + `utils/` + `pages/` + `components/` 全部 JS 不得出现 `wx.cloud.database` / `.collection()`（只剥注释、**不剥字符串**，另加「已扫 ≥ N 个文件」空断言） | 集合 ACL 是**控制台状态、CLI 读不到**，于是「代码直连 + 控制台设对」两边各自看都没问题，**只有真机炸权限错**——本地与离线回归全绿 |

**索引是文档侧的第二个坑**：只要代码里是 `where(键).limit(1)` → 查到 `update` / 查不到 `add`，键上就必须有**唯一索引**（并发防重复文档的唯一兜底）；`where + orderBy` 与定时扫描的条件要**普通索引**。这类缺口不建**不会立刻报错**，表现为「数据量上来后才超时」——测试期最难发现。文档里常见的失衡是：**唯一索引都登记了，普通查询索引几乎全缺**（加集合的人记得写唯一索引，加查询的人不觉得那算「配置」）。

> 索引**可以经 CLI 建**（`cloud_db_write_struct --action updateCollection --update-options-file`，每个集合一次 IDE 确认）——把「索引只能在控制台手建」当成前提会让你白点一遍控制台。**但有两项 CLI 既读不到也改不了，报告里必须显式列为「待人工确认」**：① 集合**权限模式**（须「仅管理端可读写」）——❗**别用 `_openid_1` 索引旁证权限**：实测 9 个集合里 7 个带该索引、2 个不带，而 ACL **全都是**「仅管理端可读写」，它只是建集合路径留下的痕迹，与 ACL 无关（曾据此误判并写进过文档）；② 云函数**定时触发器**（`config.json` 的 `triggers` CLI 不下发，`cloud_fn_info` 也**不返回** triggers 字段）。**索引是否真建了却能自动核对**：写只读脚本读线上 `listIndexes`，与文档表格的索引列比对；关键是**期望值从文档解析**而不是抄进脚本（抄一份必然漂移），且判据必须**双向**——「文档要而线上缺」与「线上有而文档没登记」都算失败。只判单向会出现「漏登记却仍打印 ✅ 完全一致」这种自相矛盾的绿。

> **给人工核对的输出要单独做一份**：差异报告（缺什么/多什么）是给**脚本**看的；人工拿着它去控制台核，缺的是**全清单**。要点两条：① 必须把**系统索引**（`_id_` / `_openid_1`）也列出来并标注「系统」，否则核对者会把它们误当成「文档漏登记的手工索引」而虚报问题——顺便这也是讲清「`_openid` 索引与 ACL 无关」的好位置；② 清单要**从线上实读生成**，别手抄（手抄必然漂移）。落地做法：同一个脚本加 `--list`（终端完整清单，供临时核对）与 `--checklist`（生成带勾选框 + 判据列的 md，供逐行打勾留档）。判据列可直接从「是否唯一」派生：唯一 → 「`where(键).limit(1)` → 查到 update / 查不到 add 的并发防重兜底」；普通 → 「服务 `where+orderBy` / 定时扫描，缺了不立刻报错、数据量上来才超时」——**派生而非每条手写**，避免同一事实在两处维护。

**变异验证（必做）**：护栏写完要注入缺陷证明它真的会红。7 项够用：删 `config.json` / 清掉 `timeout` / 删 `triggers` / 塞一个未登记函数目录 / 改代码里的集合名 / 删一个 `lib/` 副本 / 从文档表格删一行。**索引核对工具另加一项**：往文档表格**多写**一个线上不存在的索引 → 差异退出码 1，且清单里必须出现「🚨 线上缺失，待补建」行（否则「缺失」那条渲染路径从未被执行过）。**「前端零直连」那条另配三项**：往 `utils/` 塞一个真的直连文件 → 必须点名该文件转红（同时看扫描数是否 +1，证明文件真被扫）；同一份内容只写在注释里 → 必须**仍绿**（反向验不误报）；把扫描根改成不存在的目录 → 「已扫 ≥ N」空断言**必须红**。每项跑完立即还原，最后复跑回归确认无残留。

## 拆分「文档即契约」的基准文档

场景：项目有一份几百行的设定稿/契约文档，**被多个脚本当数据源解析**（表格即数据），现在嫌太长要拆。这类拆分不是「移动文件」，是**改数据源拓扑**，按下面顺序做，否则拆完静默失效。

**① 先普查引用，再动手。** 分两次 grep：一次搜文档名（谁 `readFileSync` 它），一次搜**章节号**（如设定稿里的 `§4.2` / `§6.5` 这类，看有多少引用会受影响）。真实项目形态：一份 826 行的设定稿被 **4 个脚本**读（表格列数校验、云函数结构校验、线上索引核对、表格紧凑化），正文里散着约 **50 处** `§N.M` 引用。**不知道谁在读就拆 = 拆完静默失效。**

**② 路径必须收口到单一真源。** 新增 `tools/<doc>-docs.js`，导出「全部文件清单」+「按小节号定位文件」（如 `sectionOf('4.2')`）。**绝不在各脚本里改路径字符串** —— 漏改一处的表现**不是报错、是静默读不到**：期望集为空 → 双向比对双方都为空 → 反而打印「✅ 完全一致」。这是这类拆分最危险的失效方式（比报错难发现一个量级）。

**③ 章节号一个都不重排。** 编号被代码注释、工具注释、文档正文引用（`§11 第 20 条` 这种还带条目号）。拆分只按主题**搬动**章节；新增内容一律**追加到对应分册末尾**，不插中间。并在索引页**显式写下这条规则**——否则下一个人会顺手重排。

**④ 拆分脚本自带守恒自证。** 机械化搬动（按 `^## N.` 切章 → 分组落盘），脚本内把分册正文去掉新增表头后**按原序拼回，与原文逐字节比对**，不等即报错退出。落盘前先 dry-run。复核口径用**去空白不敏感**比对（拆分只搬动、格式化只动空白，故去空白后应逐章完全相等），并把允许的差异**逐条解释**（例：顺手修了一处未转义竖线 `|`→`\|`，那它必须只是唯一差异，且要能定位到行）。

**⑤ 根文件保留原名作索引页。** 原文档名往往被注释反复提到（「见设定稿 §4.2」），改名会让这些指针失去落点。把根文件改成「元信息 + 分册导航 + 怎么用 + 文档自身护栏」，正文移入分册目录。

**⑥ 补两条只有拆分后才需要、且单册里看不出来的护栏**（进回归）：

| 护栏 | 判据 | 为什么单册看不出 |
|---|---|---|
| 索引 ↔ 磁盘双向一致 | 索引页里链接到的分册集合 = 磁盘上的分册集合 | 新拆一册忘了登记、或删册后残留死链，两边各自看都正常 |
| 章号连续、无缺口无重复 | 全部分册合并后的 `## N.` 必须从文档的 §0 起连续、无重复 | 拆分出错最易出现「跳号」或「同一章被抄进两册」 |

**⑦ 顺手检查旧护栏能不能真失败。** 被拆的文档常配着一个「只打印、从不非 0 退出」的静默校验 —— 它在回归里**永远绿**。真实样例：该脚本当时**已经抓到**一个真实缺陷（表格单元格里 `YYYY-MM-DD|HH:MM` 竖线未转义，渲染撑出第 3 列）却拦不住任何人。补退出码，并做变异验证。

**⑧ 格式化/压缩类脚本必须幂等。** 判据：**连跑两次，第二次改动 0 个文件**。真实样例：一个「表格紧凑化」脚本把分隔行规范化成 `| --- | --- |`，而文档实际格式是更短的 `|---|---|` → 每跑一次把文档**撑大** 6 字符/行；它不进回归，长期无人发现（这次跑完发现文件反而变大才揪出）。教训：先确认脚本的规范化方向与文档**实际**格式一致，再让它碰文档。

## 常见坑

| 坑 | 表现 | 处理 |
|---|---|---|
| 某目录「看起来有测试」 | 测的其实是页面逻辑，`cloudfunctions/` 结构零目标 → 缺 `config.json` 全绿逃逸 | 先数「该目录有几个回归目标」，**0 个就是缺口温床** |
| 集合清单只做单向核对 | 只看「代码用的有没有登记」，漏掉「登记了的其实没人用」 | 双向集合差，两侧都要报 |
| 测试桩 setData 直写 `this.data` | 「直接改 this.data」类缺陷**假绿** | 加 `render` 影子模型，渲染键断言读 `render` |
| 只复制函数属性建页面桩 | `this.STEP_TITLES` 之类对象属性丢失 → 崩 | 非函数自有属性也要拷 |
| 静态扫描不认识别名 | 报"传了没人读"假阳 | 先收集 `X = options` 的别名再匹配 |
| 导航正则只认字面量 url | 漏掉拼接/模板字符串调用点 → ②「读了没人传」大量假阳 | 捕获 url 表达式再抽页与键（见 ①） |
| 保护语料纳入生成器/构建脚本 | 「死代码」检查永远报 0，保护形同失效 | 保护语料只收测试/校验脚本，别收含全部标识符的生成器 |
| 静态扫描按单文件判定 | 跨文件下发的键被误报高危 | 按**归属页面**聚合（page + modules） |
| `Temp/` 未进 `.gitignore` | 临时提交信息文件被误提交 | 用 `git commit -F -` 走 heredoc，别落临时文件 |
| 页面栈语义推演 | 自绘 tabBar 用 `redirectTo` 切 tab → 栈静默累积，达上限 10 后 `navigateTo` 静默失败 | 推演/实测栈深；tab 切换应改 `reLaunch` |
| 「有 `isRelease()` 门禁 → 认为后门安全」 | 门禁只挡「直接查表」，挡不住「让云调用失败」 | 看**触发条件由谁掌握**（见 ⑤），删兜底而不是加门禁 |
| 只做源码文本断言的护栏 | 文本对、行为错 → 全绿放过（CSS 结构损坏、Promise 悬挂都曾漏过） | 能执行就执行：解析产物 / 桩环境真跑一遍 |
| 用 `_openid` 索引推断集合权限模式 | 「带 `_openid_1` 索引 ⇒ 不是『仅管理端可读写』」——实测 9 个集合带/不带混杂，ACL 却**全都是**仅管理端，该索引只是建集合路径的痕迹 | 权限属于控制台状态，**只能打开控制台看**；别用索引旁证（这条曾被写进正式文档当结论） |
| 静态扫描护栏没有「扫到几个文件」断言 | 扫到 0 个文件时护栏**恒绿**：目录改名、搬迁、正则写错都表现为「全绿」而非报错 | 加「已扫 ≥ N 个文件」空断言，并用「扫描根改成不存在的目录」变异证明它会红 |
| 校验脚本只打印、不设退出码 | 它在 `run-all` 里**永远绿**——而它可能已经抓到真实缺陷（真实样例：表格列数校验从不非 0 退出，当时就有一个未转义竖线撑列问题被它发现却没人拦） | 校验脚本必须能非 0 退出；补完立刻做变异验证 |
| 拆多册后在各脚本里改路径常量 | 漏改的表现是**静默读不到**（期望集为空 → 双向比对双方都为空 → 反而打印「一致」），不是报错 | 路径收口到一个 `<doc>-docs.js` 单一真源，脚本只经它取路径 |
| 拆分时顺手重排章节号 | 所有 `§N.M` / `§N 第 x 条` 引用（散在代码注释与文档里）集体失效，且没有任何测试会红 | 编号不重排；新内容追加到分册末尾；把规则写进索引页 |
| 格式化/压缩脚本不幂等 | 每跑一次文档涨一点（规范化方向与文档实际格式相反），不进回归就长期无人发现 | 判据：连跑两次第二次改动 0 个文件 |

## 交付物

1. 审计脚本（静态，可反复跑，输出表格）
2. 首用模拟脚本（动态，可进一键回归）
3. 云侧结构校验脚本（进回归，含集合双向一致、`lib/` 副本完整、**前端零直连数据库**）
4. 文档结构护栏（基准文档拆分为多册时才需要）：分册路径真源（`<doc>-docs.js`）+ 「索引 ↔ 磁盘双向一致」与「章号连续无重复」两条结构断言，并给旧的静默校验补上退出码
5. 分析报告：跳转图 + 触达矩阵（深度 × 门槛 → 高/中/低）+ 留存钩子接线表 + 云侧缺口（缺 `config.json` / 缺集合 / **缺索引——可由线上 `listIndexes` 自动核对，双向判据**）+ **只读核对不出来的两项**（集合权限模式、云函数定时触发器，须标注「待人工在控制台确认」）+ 优先级建议

> 报告里凡是"预估使用率"必须显式标注是**结构性推演**（无埋点数据）；并把"埋点未接导致无法测量"本身列为 P0 发现——这才是最该先修的口子。
