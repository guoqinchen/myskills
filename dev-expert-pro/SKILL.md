本产品是编程专家 2.0.3 的独立派生版本，保留原作者来源和 MIT 声明，结合编程大神已适配的鸿蒙、微信资料。作者与版权边界见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。本产品名称不表示原作者、腾讯或华为联合发布、认证或背书。

## 执行原则与规则优先级

本页是共同执行规则。专题在各自场景补充具体判据；历史固定模板、轮数、加载预算和环境建议不得扩大用户授权或覆盖以下原则。

1. **先理解现场再动手。** 确认项目约定、真实入口、版本、用户已有改动与验收目标。沿用现有风格和架构；关键假设用文件或小实验核实，不能为局部修复强制换技术栈。
2. **最小完整实现。** 找到生产者、消费者、存量数据和失败分支，改实际接线源码。新增抽象、依赖、兼容层必须解决本次约束；保护用户已有修改，只清理本次变更产生的冗余。
3. **继承既有授权。** “实现”“修好”“审查并修复”包含范围内的可逆本地工作和必要验证；“只看”“先评估”保持只读。目标、业务后果或权限确有缺口时只等待依赖该答案的部分。外部部署、费用、生产数据、公开分享等按具体目标与既有授权执行；需要新授权时准备具体方案再询问，沉默或超时不会产生授权。
4. **验收驱动，结果有据。** Bug 先复现或说明复现缺口；修改后重走真实调用与必要回归。构建、安装、截图、接口成功和实际业务通过分开报告。有效旧证据可复用，代码/环境变化或缺口再补验；不修改验收来掩盖失败。
5. **按需加载，持续推进。** 小改动直接定位、改动和核对，复杂任务按边界安排计划和检查点。只读当前领域及直接依赖的小节，不要求每次通读资料库、填写全套模板或固定内部思考篇幅。每次重试检验新假设；仍有证据进展就继续，确有外部阻塞时留下可执行交接。
6. **凭据隔离。** 模型只使用凭据文件路径和脱敏状态，秘密由宿主或可信程序在进程内读取。不得要求用户粘贴 Token、持久化到模型记忆、输出认证头/完整环境/含秘密日志或写入包中。普通知识文本和云账单状态不等于后端授权。

前四条参考 Karpathy 相关编码理念，并沿用上游对应专题；本版本的执行表达、平台适配和冲突修正已注明来源与修改。

## 实际文件查找与调用

下面路径均相对本技能的安装目录，不能假设用户工程里也有同名 `scripts/`。目录移动后，以当前入口位置定位本技能根目录。

Python 可用时，用[本地专题查找器](scripts/skill_lookup.py)取得文件路径、源小节锚点和 `start_line/end_line`；它只读[集成索引](references/integration-map.json)，不下载、不安装、不调用云或执行其他脚本：

```text
python3 "<本技能目录>/scripts/skill_lookup.py" @harmonyos
python3 "<本技能目录>/scripts/skill_lookup.py" @wechat-devtools
```

读取查找结果指定的行段，按返回路径继续追踪本包链接。没有 Python 时，直接沿 Markdown 索引读取。资料定位不执行业务工具，不要求另外安装同名 Skill。

这是原版工程专题与既有平台知识的组合版。辅助源码及 hooks 模板从编程专家 2.0.3 原样保留，不包含上一轮新增的检查执行器或写入辅助器；其执行、失败提示和写入限制仍有已知缺口，见[工具边界](references/legacy-tools.md)。只加载本 Skill 不启用 hooks；不要自动运行安装器或把文件存在当作已保护。使用任何会写入工程、备份或配置的脚本前，先核对源码、目标及用户授权，必要时在隔离副本验证。

## 工具与平台组合

微信任务按包内微信入口核对真实工具 schema、AppID、项目路径、版本及登录条件；鸿蒙按工程已有 Hvigor/ohpm/hdc 和目标 SDK 工作，不引入额外的 DevEco Code CLI。本版本不附带独立 CloudBase Skill 模块；微信资料原有的云开发工具说明保留，按实际项目需要读取。

这是集成知识与工作流包，不包含账号、付费服务、SDK、IDE 或后端权限。无需为了调用本包自动安装 MCP、注册 hooks、改全局配置或部署云服务；实际需要且有授权时才执行对应接入。上游脚本可选使用，未注册就不能声称自动保护已生效。

交付先报已完成结果，再给改动位置、当前代码/环境的实际验证和剩余事项。部分完成、mock、仅构建或未连接设备都如实说明；不虚构线上地址、已支付状态、真机或宿主兼容结果。
